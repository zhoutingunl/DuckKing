# 语音教练 × 变速倾斜圆盘：MicroDuck 平衡挑战

研究日期：2026-11-01。范围仅为调研与设计；未修改应用、训练策略、运行圆盘仿真或部署。这里的“可尝试”不代表已经站稳，也不代表任意转速/倾角下物理可行。

## 1. 能站稳吗？先明确“站稳”是哪一个任务

### Takeaway

**这是值得作为演示主角的仿真 PPO 新技能：圆盘运动连续变化，观众可用真实 Linx 语音当教练，小鸭闭环应对。** 技术方向有希望，但目前未验证。第一阶段应限定为“靠近圆心、允许随盘转动、在已验证的速度和倾斜范围内保持站立”；高速外圈、始终面朝观众和任意变速是更难的独立任务，不能一并承诺。演示优先级高，不代表实现最容易或训练最便宜；工程上仍要先完成动力学对齐、策略运行时和有限扰动实验。

### Cited Findings

- 2019 年原始论文研究 NAO 在旋转平台上的平衡，平台角速度作为未知扰动；摘要报告的是**仿真结果**，算法结合模型式强化学习与 Q(λ)，不是 MicroDuck 或 PPO 的成功记录。本次未核实其平台全部旋转轴定义，因此不把论文标题当作“高速自旋加双轴倾斜已解决”的证明。— [Xi 等，IEEE/CAA JAS 原论文页面](https://www.ieee-jas.net/en/article/doi/10.1109/JAS.2019.1911567)
- NTNU 的 PPO 平衡板项目在 Isaac Gym 中学习控制关节来保持人形机器人与平衡板稳定，观察包括机器人状态、脚位置和板状态；可作为“低层关节策略＋移动接触面”的先例。它不是 MicroDuck，也不是高速自旋圆盘验证。— [作者项目与代码](https://github.com/NTNU-ERC/Robinion-Balance-Board-PPO)
- MuJoCo 支持单转轴 hinge、自由根关节、接触摩擦与执行器输出限幅，足以表达有惯性和有限驱动力的转盘及自由站立机器人；这些只是建模能力，不是策略成功保证。— [MuJoCo 3.3.7 关节定义](https://mujoco.readthedocs.io/en/3.3.7/XMLreference.html#body-joint)、[执行器定义](https://mujoco.readthedocs.io/en/3.3.7/XMLreference.html#actuator-general)
- MicroDuck 官方策略有 14 个受控舵机，包含两腿及头颈；官方强调归一化、关节索引和执行器模型的一致性。项目审计里的 2D 导航 PPO 只发速度命令，不能被当成已经具备平台平衡能力。— [官方固定版本说明](https://github.com/pollen-robotics/microduck_rl/blob/bae39f5900b318f7e87fc485c30a31213cfa14eb/AGENTS.md)、[本项目训练审计](ppo_training_audit.md)

### Inferences

以下是物理分析与方案判断，未经 MicroDuck 实验验证。

| 任务 | 成功定义 | 为什么不同 | 建议 |
|---|---|---|---|
| A. 靠近圆心、随盘转动 | 不跌倒，双脚保留足够盘边余量，躯干姿态可用，允许偏航跟随盘面 | 圆心附近的平动需求较小，但两脚并非同时处于旋转轴；加速时仍要传递力矩，倾斜时仍需调节姿态 | 首期。展示为“变速倾斜盘平衡”，不要叫“始终面向观众”。 |
| B. 保持世界朝向 | 除 A 的平衡条件外，机身朝向持续跟踪世界坐标中的观众方向 | 需要换脚/转步抵消盘转；双脚无限期粘在盘上又让身体保持世界朝向不符合有限关节行程。仅转头也只能覆盖有限角度 | 单独的条件策略或后续阶段，明确允许迈步。 |
| C. 靠近外圈不滑出 | 从偏心位置保持/回到允许区域，整个足底不越盘边，并保持站立 | 同转速下偏心距离增大会增加向心力需求；少量滑移即可能耗尽盘边余量，身体站直也可能整体滑出 | 后续难度，不把“盘中心站住”扩大成“任意位置站住”。 |

一个仅用于解释的近似：平盘、恒定角速度、点质量随盘运动、法向力约为 `mg` 时，保持不滑动需要 `ω²r ≤ μg`。这里 `r` 是偏离旋转轴的半径，`μ` 是简化静摩擦系数。**这是极简情形的必要摩擦约束，不是双足稳定的充分条件。** 它忽略有限支撑区域、重心高度、足底力矩、执行器能力、加速产生的切向需求、倾斜的重力分量和法向载荷变化。即使满足它，也可能翻倒；不能由此计算出一个“MicroDuck 安全最高 RPM”。

真实设计应同时限幅：盘转速、角加速度、角加加速度（jerk）、两轴倾角、倾斜速度与加速度，并按离圆心距离限制任务。先从静止到慢速，小倾角、慢变化开始。“飞转”的观感可来自清晰盘面刻度与固定机位，不应靠提高到未验收的速度。本文不提供看似精确但未经测量的 RPM/倾角承诺。

### Gaps

- 尚未建立 MicroDuck 的圆盘尺寸、脚底摩擦、可用关节力矩和稳定范围；不能回答“当前策略已经能否站稳”或“最高能多快”。
- 未发现直接证明“MicroDuck 在高速变速、双轴变倾角圆盘上站稳”的原始实验。现有先例只支持研究方向有依据。

## 2. 如何建模与训练，才能称为学到平衡？

### Takeaway

圆盘必须通过有质量、有惯性、有限驱动力的物理关节运动，小鸭靠足底接触支撑。首期应训练专门的低层 14 关节 PPO 或受限关节残差策略；已有 2D 导航 PPO 适合作为后续目标选择层，不足以单独承担这个任务。

### Cited Findings

- MuJoCo 的 hinge 围绕指定轴/位置旋转，`forcelimited`/`forcerange` 可以限制执行器输出。模型中存在这些配置，不代表参考轨迹的加速度或 jerk 自动受限；轨迹生成与限幅仍须实现并验证。— [MuJoCo 3.3.7](https://mujoco.readthedocs.io/en/3.3.7/XMLreference.html)
- 官方 MicroDuck 工作流要求先检查物理可行性，并保持模型、BAM 执行器、observation 和导出归一化一致；本项目已有 BAM 与最终 XML 执行器差异需要先处理。— [官方开发说明](https://github.com/pollen-robotics/microduck_rl/blob/bae39f5900b318f7e87fc485c30a31213cfa14eb/AGENTS.md)、[本项目训练审计](ppo_training_audit.md)

### Inferences

以下全部为拟议设计，不是已实现配置。

**物理模型：**固定基座 → 两个有限角度的倾斜轴/万向框架 → 盘法线方向的自旋 hinge → 有厚度和惯性的圆盘。明确轴顺序，保证“倾斜＋自旋”有唯一解释；只从实际关节状态计算盘面速度。用受限位置/速度控制器驱动平滑参考轨迹，记录目标与实际运动。Duck 根部为自由体，足盘由碰撞和有限摩擦传力。

禁止将双脚焊在盘上、每步重写机器人根部 `qpos`、给躯干隐藏稳定力、无限摩擦、删除关键碰撞或把画面旋转当作物理盘转。平台电机是公开的环境驱动，PPO 只控制鸭的关节。初始 reset 可以把鸭放上盘；展示期间不能靠重置救回且继续计成功。

**观察与动作：**

- 首期研究版 actor 可用关节角/速度、机身重力投影、角速度、上一动作及短历史，另加盘的实际姿态/角速度、鸭相对盘中心位置、足盘相对状态、当前任务模式/朝向目标。精确盘状态、接触和相对位置来自模拟器时，UI 写“仿真真值感知”，不得说成相机看出来。
- critic 可拥有更丰富的接触/力矩/环境参数。若 actor 使用了精确平台未来轨迹或摩擦系数，必须明示；更有说服力的首期让 actor 只看当前/过去状态及已下达运动命令，不读取尚未发出的未来扰动。
- 面向未来真实机器人，可研究机身本体感知历史估计平台运动，或使用真实平台编码器/IMU；仅本体感知很难可靠知道离盘边多远，应增加可验证定位/视觉/平台传感。观测删掉真值后必须重新验证，不能默认仍会平衡。
- 控制器路线分三级：先以冻结官方步态/姿态策略为基线；再研究按控制频率输出的 14 关节有界残差 PPO，例如 `q_ref = q_base + clip(Δq, −δ, δ)`，对最终目标另外施加关节位置/变化率约束；若残差动作范围不足或基策略持续对抗所需平衡动作，再训练独立 whole-body PPO。三者均保持正确舵机顺序、执行器与控制速率。`δ`、动作变化率和稳定性必须实测，不能仅凭公式声称安全或可迁移。
- 现有 ONNX 主要用于推理，不能当作天然可继续训练的 PPO checkpoint；它可能没有 critic、optimizer 状态，也未提供可供续训恢复的 observation normalizer 状态。可以冻结 ONNX 的推理输出作为残差基策略，但若要微调原策略，须先获得并检查真实训练 checkpoint 和训练配置，不能承诺无缝续训。

**课程与奖励：**

1. 平盘静止：确认 nominal stance 在实际执行器模型下可站立；用小初态扰动检查接触、质量、关节顺序和动作方向。
2. 分别训练：只倾斜的慢扰动；平盘低速自旋与缓慢变速。先让策略分别学会两类扰动。
3. 组合：两轴倾斜＋转速变化，限定中心区；使用平滑但非固定周期的训练轨迹，避免只记住一条正弦。
4. 扩大分布：随机摩擦、轻微质量/重心变化、动作与感知延迟、初始位置/朝向、扰动频率/相位，限制在物理可行区。训练与评估都包含减速停止过程。
5. A 稳定后，分别加入 B 的世界朝向目标与合法换步、C 的偏心初态和回中心任务；不要同时加全部难点。

奖励组合建议：保持可用姿态和高度、留在任务允许区域、有效支撑、关节动作平滑、必要时跟踪世界朝向；惩罚支撑脚相对盘面滑移、脚接近边缘、过大力矩/动作速率与非预期身体接触。允许迈步的阶段，不能把摆动脚的所有运动都误罚为“滑移”。成功与失败应由独立状态判定，防止跪着、趴着或贴边拖行获得高存活奖励。

足盘滑移应比较**接触点的足速度与该处盘面速度**，不是比较足的世界速度与零。盘面速度可由 `v_center + ω_disc × (p_contact − p_center)` 得到，再投影到盘面切向。盘边余量检查整个足底投影/有效接触区域，不能只看机身中心或脚中心。

力学诊断可记录接触合力、压力中心/支撑区域和姿态；在倾斜加速表面上，不能直接套静止水平地面的“重心投影在脚内就安全”或简单 ZMP 判定。

### Gaps

- 尚无训练记录，不能指定 PPO 样本量、GPU 用时或成功率。首轮只需要配置 smoke test 与短训练观察，不承诺现场几秒训练成功。
- 14 关节平衡策略的 observation 与原 61 维策略可能不同，需要专门导出和运行时适配；这不是只换一个 ONNX 文件。

## 3. 如何让 Linx 语音成为节目核心，并用真实证据展示进步？

### Takeaway

节目可叫“语音平衡教练”：评委实时改变转盘挑战，小鸭确认任务、给出可观测状态、执行有界停止。训练前、早期与训练后策略面对同一组扰动，让观众看见真正学到的差别。

### Cited Findings

- 本项目要求区分动画预览、真实 MuJoCo/robotd 连接及 Linx 实时云语音，不得因后端失败静默切换预览或把本地台词称为云响应。— [仓库约束](../../AGENTS.md)
- PPO 依靠环境采样与策略优化；语音改变已支持参数/目标，与当场训练出新能力是不同过程。— [PPO 原论文](https://arxiv.org/abs/1707.06347)

### Inferences

**五轮现场对话（设计示例，回复必须以实际状态为依据）：**

| 轮次 | 人说 | 小鸭通过真实 Linx 回复与实际行为 |
|---|---|---|
| 1. 准备与确认 | “小鸭，准备好了吗？今天挑战旋转圆盘。” | 检查真实平台静止、足部支撑及策略就绪后：“准备好了，我现在在中心区。先用慢档吗？” 未就绪则报告具体原因，不播放准备成功台词。 |
| 2. 语音定义任务 | “慢档开始，随盘转，保持十秒。” | “慢档、保持中心，计时开始。” 任务编排器将命令转为已验证配置，物理盘平滑加速；策略根据状态调节关节。计时以真实开始事件为准。 |
| 3. 在线增加扰动 | “快一点，再向右倾一点。” | “正在切到二级速度和右倾档，逐步增加。” 只接受已验收的组合，并显示目标/实际转速、倾角与变化率。新指令取消旧调节目标，但不跳变平台状态。超范围时明确说明最高已支持档位。 |
| 4. 观测与纠正 | “现在还稳吗？有风险就别再加速，往中心回来。” | 根据真实余量/滑移回答“出现滑移，已停止增加转速”。在 C 的回中心能力已训练后才执行回中心，并随后报告结果。首期 A 没有回中心能力时，只开放“降低难度/停止挑战”，不临时编造新能力。 |
| 5. 有界停止与复盘 | “停止圆盘，告诉我刚才怎么样。” | “开始减速并逐步放平，我继续保持平衡。” 盘通过受限运动轨迹真正停止，鸭继续闭环；满足实际转速/倾角容差后才说“圆盘已停。刚才保持了 X 秒，出现 Y 次滑移/越界”。X/Y 来自记录事件。 |

**停止必须有两种清晰语义：**

- “停止圆盘”是物理动作：平滑降低实际角速度、受限放平倾角，PPO 持续工作，物理时间继续推进；停止时限取决于当前状态和验证过的减速能力。不能直接把角速度设零，也不能先回复“已停”再慢慢停止。
- “紧急暂停仿真”才冻结 MuJoCo 时间，UI 持续显示暂停。它是演示保护操作，不是鸭成功完成物理急停，也不应把该回合计作完整成功。
- 临近跌落、状态中断或策略异常时，本地监督器可停止接受新挑战并触发预定义减速/紧急暂停；云语音延迟不能进入平衡控制环。必须保留失败原因；不换成动画或台词掩盖。

**语音与控制分层：**真实 Linx 会话负责意图和反馈 → 有界任务解析器负责目标/档位/取消 → 平台轨迹生成器负责可实现的扰动与减速 → 本地 PPO 高频推理控制 14 关节 → 独立评估器产生准备、滑移、越界、跌落、停止完成事件。平台参数仅在已验证范围内切换；“再努力一点”可以解释为请求重试/降低难度，但不意味着权重在线更新。

**公平验收与展示（拟议）：**

1. 比较 nominal 关节姿态保持、现有固定策略、早期 checkpoint、新训练策略；相同平台轨迹 seed、初态、摩擦和执行器配置成对评估。早期 checkpoint 必须来自真实训练，不制作假失败动画。保留未见的变速/倾斜组合，避免只测训练轨迹。
2. 成功定义同时包含：完整挑战时长、没有身体跌落/非预期接触、足底没有越盘边，并完成减速停止。A 不要求世界朝向固定；B 另统计机身朝向跟踪误差；C 另统计回中心耗时。每个任务单独报告。
3. 记录站立时间、身体倾角分布、支撑接触中断、接触点切向滑移距离/速度、最小盘边余量、跌落率、关节限幅/力矩、平台目标与实际运动误差，以及停止过程的失稳次数。
4. 语音同时记录：用户语句结束→意图识别、意图→执行器接收、用户语句结束→首次真实物理响应、请求停止→物理停止完成、首次语音确认延迟。使用 p50/p95 等分位数，避免只报最好一次；语音早确认不等于物理已完成。
5. 现场画面显示当前策略、真值感知标签、实际转速/倾角、脚滑移/盘边余量、云语音状态。可先做三分屏相同 seed 的基线/早期/训练后对照，再让评委现场变更已支持档位；预录对照清楚标注，现场挑战也允许失败并诚实复盘。

这项可替代原“摇摆平台”成为首选候选：语音能持续改变可观测挑战，PPO 的身体协调直接可见，任务成功无需靠编排台词。但首期优先证明 A，再扩展 B/C；“飞转”应等实测稳定范围支持后再作为宣传措辞。

### Gaps

- 上述对话没有真正通过 Linx，所有响应与延迟均待实现验收；不构成已完成云语音集成的证明。
- 尚未生成任何圆盘训练曲线、checkpoint、对照视频或成功率，不能将本笔记中的验收方案写成比赛成果。
