研究日期：2026-10-26。冻结时间采用用户最新指示：2026-10-27 09:00 Asia/Shanghai。本笔记只作研究和设计，不代表已经实现、实机测试或真实云端验收。未修改应用、未连接真实云会话/设备、未发送外部消息。用户已确认目前只有仿真、暂时没有实体机；本轮所有推荐场景按仿真产品原型设计。未实现功能均为设计提案，实体机能力仅列后续路线。

## 1. 灵矽官方支持什么，DuckKing 尚缺什么？

### Takeaway

灵矽已经给出语音、工具调用、逐句行为信号、视觉和记忆的协议入口；多数“具身”体验仍需设备端实现传感、动作、状态机和回执。本轮最有价值的是让现场真人通过灵矽实时语音，改变仿真中的任务与动作，系统根据实际仿真结果回应并承认不确定；实体语音接入是后续完成竞赛题目硬件部分的必要路线。

### Inferences

- 用户已确认只有仿真。本轮顺序调整为：浏览器真人拾音 → 灵矽实时工具调用 → robotd/MuJoCo 动作回执 → 可打断的对话动作表达 → 一个有用的任务状态机。机身音频、相机和传感器列后续硬件路线。
- 相对投入：情绪/行为白名单映射和现场导演为小到中；计时器/动作宏为中；相机为中到大，取决于采图是否已通；实体搬运、真实 BLE、多机协作为大，取决于机械和设备库存。以上是范围判断，没有实测工时依据。
- 初版物理按钮讲话是合理的语音交互；“装在鸭里”的证明重点是输入和输出端确在机身、云端结果驱动实机。不要为了免按键而牺牲稳定性。
- 表情控制应采用“保护/停止 > 显式工具动作 > 对话微动作 > 空闲动作”的优先级，并共享取消代次。否则逐句点头可能覆盖夹持、走路或停止动作。

### Gaps

- 用户已确认没有实体机，因此未验证机内音频、相机、夹持、电量/温度遥测或第二台设备。不能以这些功能为周二演示前提。
- 未验证真实 agent 的已启用模型、情绪标签全集、音色、记忆、知识库、外部 MCP 及其权限；本次没有发起云会话。
- 长期记忆入门页与 Agent API 的模型标识示例存在不同写法，且入门有示例域名；集成时以当前 API 与账号配置校验，不照搬教程片段。[长期记忆入门](https://linx.qiniu.com/docs/xrobot/guide/longterm-memory-start)、[Agent API](https://linx.qiniu.com/docs/xrobot/api/agent)

## 2. 当前演示为什么有趣，但仍不足以完整证明竞赛主题？

### Takeaway

现有演示擅长展示动作编排、取消以及仿真物理回执，适合作为工程证明。产品叙事应再回答“我什么时候会需要这只鸭、它如何理解临场变化、身体带来什么价值”，并清楚说明当前完成的是灵矽语音 + 官方仿真的产品原型；真实机身语音链路仍是后续主题硬件部分的门槛。

### Cited Findings

- 目录包含 12 个场景：身份问答、反向招聘、打断、临时改需求、踢球、递送、双房间斗舞、寻友、组团出道、四声部、桌上演出、坐站独唱。大部分以预设台词和动作序列组织。[demo-catalog.js:1](/Users/zhouting/Documents/QiNiuWork/github_base/DuckKing/frontend/src/demo-catalog.js:1)
- 演示运行器区分本地脚本和预录输入触发实时云端响应；四声部、桌上演出、坐站独唱三个场景强制本地模式，不能作为灵矽实时回答证据。[demos.js:26](/Users/zhouting/Documents/QiNiuWork/github_base/DuckKing/frontend/src/demos.js:26)、[demos.js:256](/Users/zhouting/Documents/QiNiuWork/github_base/DuckKing/frontend/src/demos.js:256)
- 当前提示词诚实区分固定道具、实际执行回执、本地合成音频和模拟同伴信息，并禁止伪称真实硬件/视觉能力；这一点应保留。[onboarding.py:28](/Users/zhouting/Documents/QiNiuWork/github_base/DuckKing/src/duckking/onboarding.py:28)、[onboarding.py:34](/Users/zhouting/Documents/QiNiuWork/github_base/DuckKing/src/duckking/onboarding.py:34)、[onboarding.py:40](/Users/zhouting/Documents/QiNiuWork/github_base/DuckKing/src/duckking/onboarding.py:40)

- `_local_done` 返回本地文字结果，没有本地 TTS；本地 ASR 路由仍依赖浏览器能连接本地/局域网服务及 ASR 已安装启用。[hybrid_voice.py:96](/Users/zhouting/Documents/QiNiuWork/github_base/DuckKing/src/duckking/hybrid_voice.py:96)、[hybrid_voice.py:166](/Users/zhouting/Documents/QiNiuWork/github_base/DuckKing/src/duckking/hybrid_voice.py:166)

### Inferences

- 保留“打断”和“改需求”的工程能力，合成一个真实临场场景；保留已验证轻物递送作为具身闭环候选；音乐缩成十秒结束彩蛋，并标明本地合成。
- 双房间、斗舞、多声部、坐站唱歌有重复的观感收益。主秀只保留一种多人感/表演，节省时间给追问、失败恢复、真实感知和有用任务。
- “孤独鸭寻友”如使用仿真视野和对象真值，应称仿真同伴查询；不能据此说已实现相机认鸭、真实 BLE 发现或自主追随。
- 当前草稿叙事中的离线能力、拒绝策略、跌落后再踏步必须降到已实现边界。尤其不要用桌边跌落证明避险，不把恢复站姿命令写成任意姿态摔倒自起。
- 每个主秀至少让评委改变一个输入：临时换顺序、打断、换一个物品、提出模糊指代或取消提醒。系统应当重算、澄清或承认失败，而非继续固定台词。

### Gaps

- 未知比赛评分细则，不能声称创意/技术/完成度各占多少分；本文仅用主题贴合、实用价值、惊喜和可稳定验证作建议标准。
- 没有实体设备日志、真实音频链路记录或传感器结果；当前代码读审不能替代实机验收。

## 3. 推荐的十个产品场景及四个备选怎样设计？

### Takeaway

下列都是仿真产品原型设计，不宣称现有代码可直接演。推荐十个主体场景均以单鸭为中心；共同验收要求是“现场真人不同输入 → 灵矽实时理解/工具调用 → 正确调整任务 → MuJoCo 可见动作 → 仿真结果/失败回执”。感知使用仿真状态时必须显示来源；相机、触摸和真实遥测均不作为本轮前提。

### Cited Findings

- 当前已经有点头、摇头、转向、坐站、舞蹈、固定道具踢球/搬运及停止等可用于场景原型的动作入口；实际实体可执行范围仍需另验。[demo-catalog.js](/Users/zhouting/Documents/QiNiuWork/github_base/DuckKing/frontend/src/demo-catalog.js)、[onboarding.py](/Users/zhouting/Documents/QiNiuWork/github_base/DuckKing/src/duckking/onboarding.py)
- 平台提供工具调用和视觉、状态消息入口，但不会自动创建以下任务状态机或硬件动作；这些设计因此列在 Inferences 中。[端侧 MCP](https://linx.qiniu.com/docs/xrobot/mcp/hardware-mcp)、[摄像头接入](https://linx.qiniu.com/docs/xrobot/guide/camera-feature)

### Inferences

#### 1. 专注搭子：“到点叫我，但别抢我的会”

- **用户/时刻与价值：** 开发者进入专注时段，需要不会不断刷存在感的桌面提醒器。
- **真实说法：** “陪我专注二十五分钟。”鸭问“到点叫你一次，还是先轻声提醒？”用户说“先轻声。等一下，我要开会，推迟十分钟。”
- **身体与闭环：** 坐下进入安静态；定时到点轻抬头、一次提示；延期更新同一个任务，取消后不再提醒。不能靠对话模型自己记时间。
- **15–40 秒高潮：** 演示明确设置十秒测试计时，中途延期，旧到期点鸭保持安静，新到期点才站起说话。
- **复用/最小新增/硬件：** 复用坐站、取消、云端语音；新增可靠定时任务、状态查询、延期/取消与主动播报适配。本轮使用浏览器真人拾音与仿真鸭，相机非必需。
- **可测成功条件：** 原任务到期零播报，新任务恰好播报一次；“取消”后等待超过到期点仍无动作；日志能对上任务 ID 和修改版本。相对投入：中。

#### 2. 桌面检查员：“东西没齐，先别宣布完成”

- **用户/时刻与价值：** 把离开工位前核对物品的需求做成可见交互原型，用户可现场修改清单和摆放。
- **真实说法：** “出门前帮我检查球和小棒都在收纳区。”鸭澄清“按屏幕上标记的区域吗？”用户说“今天不用小棒，先只查球。”
- **身体与闭环：** 鸭朝对应对象/区域注视，从 MuJoCo 对象位置查询是否在目标区域，按新清单判断。界面始终显示“仿真状态查询，非摄像头识别”。
- **15–40 秒高潮：** 用户将球移出指定区，鸭报告缺项；将球放回后复查，由未完成变为完成。
- **现有/新增：** 复用世界中的球、小棒和对象位置/结果检查；新增只读物品位置工具、区域定义、清单增删与 `look` 表达。若当前对象位置未暴露给 MCP，必须开发查询工具，不能由 LLM 猜界面。
- **可测成功条件：** 回答对应最新仿真状态；清单修改立即生效；未知对象明确说不支持；移动到区域外不仍报完成。相对投入：中。未来可把状态源替换为相机，但不预先声称具备。

#### 3. 嘴硬快递员：“替我挪一点，听得懂反悔”

- **用户/时刻与价值：** 在固定桌面站点间递送一枚专用轻质消息牌/小棒，不承诺通用抓取。
- **真实说法：** “把这个送右边。”鸭先问“右边标记台？”用户途中改口“先停，放到左边吧。”
- **身体与闭环：** 在已验证抓取区夹取、短距离搬运、放下；停止时先安全保持当前状态，再根据可达性执行新任务。夹取失败就说明失败，不能仅演完动作宣布送到。
- **15–40 秒高潮：** 移动中一句“停”，鸭停下；用户改目的台，最终道具落到新目标。
- **复用/最小新增/硬件：** 仿真已有轻物夹持/搬运/放置结果检查，可复用任务结构；本轮限定现有仿真小棒，新增命名目标区、途中改目的地与任务状态。若现有控制只能固定夹取/放置，就先限制在能可靠执行的位姿；实体夹持列未来路线。不能将仿真固定小棒泛化成手机、水杯或任意笔。
- **可测成功条件：** 停止后旧任务不继续；成功需目标区物体状态或人工可核验放置结果；失败时不报送达。相对投入：中；实体迁移另计。

#### 4. 会议小主持：“会提醒，也知道自己闭嘴”

- **用户/时刻与价值：** 小组站会控制轮次与时间，避免主持人反复看表。
- **真实说法：** “每人一分钟，先小李再小王。”鸭复述名单；用户改口“小王先，今天别报剩余时间，只在超时提醒。”
- **身体与闭环：** 用朝向或站姿指示当前轮次，超时轻点头/提醒；用户“下一位”“暂停”驱动确定性队列。姓名由显式指令绑定，不假设已做人声身份识别。
- **15–40 秒高潮：** 使用明确标注的短轮次，临时换顺序并暂停；鸭恢复时接着正确的人/剩余时间。
- **复用/最小新增/硬件：** 复用注视/转向、坐站、取消；新增轮次队列、暂停恢复和名单澄清。单鸭即可，固定座位标记可降低定位需求。
- **可测成功条件：** 修改名单后恰好按新顺序轮转；暂停期间不播报；停止会议清除后续提醒。相对投入：中。

#### 5. 安静陪伴：“今天不用劝我，陪我待一会儿”

- **用户/时刻与价值：** 用户疲惫时想要低负担陪伴，不需要不断被建议或提问。
- **真实说法：** “今天不想听大道理，陪我安静十秒。”鸭简短确认；中途用户说“现在可以说一句了”；可选屏幕“模拟摸头”事件必须显式标注。
- **身体与闭环：** 坐低、轻倾头、安静等待；用户再次开口即退出静默；若接入模拟摸头事件，仅以微动作反馈，并不宣称真实触摸感知。情绪由用户表达，不推断疾病或承诺治疗。
- **15–40 秒高潮：** 鸭真的保持沉默；用户重新说话后它能接上刚才的偏好；模拟摸头只产生微动作。
- **复用/最小新增/硬件：** 复用坐站/点头、语音取消；新增静默状态和逐句表情仲裁。本轮只需语音状态与仿真动作；模拟摸头事件是可选 UI 扩展，真实抚摸检测留到硬件路线。
- **可测成功条件：** 静默计时内不擅自长篇回答；用户打断立刻结束等待；触摸误触不会启动行走。相对投入：中；触摸作为可选增强。

#### 6. 语言游戏官：“鸭王说，才可以动”

- **用户/时刻与价值：** 亲子/英语/方向词小游戏，训练注意和规则表达；身体是可观察的答案。
- **真实说法：** 用户设规则“只有我先说‘鸭王说’你才能动。”先说“向左转”，再说“鸭王说向左转”；接着“刚才不算，改成‘船长说’”。
- **身体与闭环：** 不符合规则保持静止，符合才执行有界动作；解释为什么没动；改变口令更新游戏规则，不能靠一组预录词匹配表演。
- **15–40 秒高潮：** 评委用陷阱句诱导失败，鸭守住规则；立刻改变规则后第二轮仍能遵守。
- **复用/最小新增/硬件：** 复用受限动作和停止；新增独立游戏状态、规则解析/确认、计分，云端负责解释。不能直接复用当前会拒绝条件句的离线解析器假装已完成。
- **可测成功条件：** 预设正反测试句中无前缀零动作；新口令生效后旧口令不动作；“退出游戏”解除约束。相对投入：中。

#### 7. 会追问的橡皮鸭：“先别给答案，帮我把问题讲清楚”

- **用户/时刻与价值：** 开发者卡住时，通过口述和被追问理清假设。
- **真实说法：** “接口能打开，为什么前端还是失败？先别给方案。”鸭追问“是浏览器报错，还是返回内容不对？”用户说“是浏览器，而且刚才那个请求其实没发出去。”
- **身体与闭环：** 听时抬头，发现缺信息时倾头，得到澄清后点头；复述已确认事实并给一个下一步检查，避免一次讲十种原因。
- **15–40 秒高潮：** 用户故意补充一个推翻早先判断的事实，鸭撤回旧假设、调整下一步；“停，我只要一个检查”能立即压缩回应。
- **复用/最小新增/硬件：** 复用灵矽对话、打断、基本动作；新增角色约束、短上下文问题状态、情绪/行为映射。本轮通过浏览器真人拾音控制仿真姿态；无需访问真实代码库或摄像头，若后续接知识库再明确来源。
- **可测成功条件：** 先澄清再建议；每轮最多一个问题/检查；用户推翻事实后不继续复用旧结论。相对投入：小到中。

#### 8. 自定义仪式：“把这个叫作‘下班’”

- **用户/时刻与价值：** 为个人或团队建立可修改的简短仪式，语音成为教设备的接口。
- **真实说法：** “以后我说‘下班’，你先点头，再坐下，最后说今天辛苦了。”鸭复述；用户说“别说话了，把最后一步删掉。”随后再次说“下班”。
- **身体与闭环：** 创建/编辑一个允许列表内的有界动作宏；展示最新版本、执行结果；“取消”清除当前动作链而不是只停止 TTS。
- **15–40 秒高潮：** 现场教一个新名字，修改其中一步，立即按修改后的定义重放。
- **复用/最小新增/硬件：** 复用动作序列、上限和取消；新增宏的结构化存储、命名/编辑确认和版本。不能执行任意生成代码，不把临时上下文当持久保存。
- **可测成功条件：** 重复调用得到相同有界序列；删除的步骤绝不出现；同名冲突先澄清；取消后旧余项不再执行。相对投入：中。

#### 9. 互动踢球教练：“没踢中，就一起改方法”

- **用户/时刻与价值：** 把物理小游戏做成会解释反馈的教学玩具：尝试、观察、调整，而不只是发出踢球口令。
- **真实说法：** “教我用左脚把球踢进那个框。”鸭先确认目标框；尝试后用户说“刚才没碰到，换右脚试试。先别踢，告诉我准备好了没有。”
- **身体与闭环：** 查询球与脚/目标位置，区分已就位、执行动作、确有接触、球进入目标区四个状态；不能执行完踢腿便报进球。必要时要求用户把球放入支持的位置，不声称自主找球。
- **15–40 秒高潮：** 先故意把球放在不可接触的位置，让鸭说明失败/缺少条件；修正位置后再踢，按 MuJoCo 接触和位移报结果。
- **现有/新增：** 复用左右脚踢球、接触/位移证据；新增教学回合、目标区域、评分和“准备/执行”分阶段对话。定位数据明确是仿真状态。
- **可测成功条件：** 无接触不得计分；换脚使下一回合计划更新；“先别踢”仅检查状态不执行；成功与失败都能追溯物理结果。相对投入：中。

#### 10. 临场小导演：“一句话让它改戏，而不是重放”

- **用户/时刻与价值：** 家庭讲故事、活动主持、创意玩具；孩子/评委临时决定角色和动作顺序。
- **真实说法：** “演一只想上班又不想上班的鸭，先兴奋再泄气。”表演中用户改口“不要走，只用头表现；最后加一句‘我先喝口水’。”
- **身体与闭环：** 把情节分成少量白名单动作/语音段，逐段执行；新约束中断旧段并重排，不重新播放同一固定剧本。动作表达受有界策略控制。
- **15–40 秒高潮：** 评委给一个未预录的心情/顺序/结尾，现场再改一个约束；鸭立刻换演法。
- **复用/最小新增/硬件：** 复用现有云工具调用、动作取消、点头/摇头/坐站；新增简短计划状态、逐句表达映射和约束检查。本轮只需仿真基础动作和浏览器实时语音，无相机依赖。
- **可测成功条件：** 新约束后不再走路；旧台词/动作不残留；每段结果可对上工具回执；未预录输入确实来自现场麦克风。相对投入：小到中。

#### 四个备选，按资源再取舍

11. **物品记忆员“你把钥匙放哪儿了”**：用户明确让鸭观察固定托盘并记录一次；次日追问时鸭给“上次看到的时间/位置”，不保证物品仍在。模糊的“那个”先澄清，移动后必须重拍。新增采图、可删除的事件记录、标签区域；成功标准为回答区分历史记录与当前观察。与场景 2 二选一，避免视觉清单和物品记忆重复占主秀。

12. **晚安开关“灯关了，我也坐下”**：一个安全桌灯通过真实云 MCP 改状态，再读取确认；用户改口“留一盏”时先澄清灯名。成功标准是读回状态吻合，不是只收到 API 200。新增外部服务绑定和设备映射；没有可用服务就不演，不能拿界面动画冒充灯。

13. **自我照顾“我现在该休息了”**（硬件后续路线）：读取真实电量/温度后选择允许动作，传感器缺失返回未知，禁止假装走回充电座。本轮如用注入数值演示策略，必须标为“模拟状态”，不宜占主秀位置。

14. **临时组团“新朋友来了，给它留一个角色”**（唯一多鸭扩展）：真实第二台鸭加入时发现并分配角色，离开后单鸭接替；用户改角色，所有成员应更新。需真实身份发现/BLE 与多机状态协议，当前浏览器双房间不能证明这些能力。成功标准是物理设备离开后停止等待旧角色，不把本地合唱当云端多智能体。硬件/时间成本最高，本轮不优先。

### Gaps

- 以上成功条件是建议验收标准，不是本次已运行的测试。具体停止延迟目标应在实体控制频率、音频链路和动作边界实测后确定，不能直接宣称某个毫秒值。
- 抚摸检测、抱起暂停/放下恢复、BLE 等官方候选由 Microduck 研究笔记提供进一步证据；本笔记没有独立实机验证。姿态表达可先采用现有动作，`robot.look` 集成后再精化。
- 宏存储、日程、物品记忆和情绪仲裁目前都是待开发；不可写成“支持”的现状介绍。

## 4. 只有仿真时，优先做哪三个，现场如何串成 3–5 分钟？

### Takeaway

用户已确认暂时没有实体机。建议本轮优先“专注搭子 + 临场导演 + 互动踢球教练”：分别证明有用任务、自然语言临场修改、物理结果闭环；从现有世界复用最多，避免引入未经验证的相机或实物前提。

### Cited Findings

- 当前浏览器可采集真人语音；演示已有实时云端与本地脚本的模式区分，但预录 WAV 进入云端不等于已验收现场真人说话。[voice.js:89](/Users/zhouting/Documents/QiNiuWork/github_base/DuckKing/frontend/src/voice.js:89)、[demos.js:26](/Users/zhouting/Documents/QiNiuWork/github_base/DuckKing/frontend/src/demos.js:26)
- 当前踢球/轻物动作有仿真结果检查，适合做真实执行反馈原型；本地歌曲与实时云响应仍需保持区分。[demo-catalog.js](/Users/zhouting/Documents/QiNiuWork/github_base/DuckKing/frontend/src/demo-catalog.js)、[onboarding.py:40](/Users/zhouting/Documents/QiNiuWork/github_base/DuckKing/src/duckking/onboarding.py:40)
- 官方接入流程还包括设备固件、激活/绑定和机身通话，网页与仿真无法替代这部分完成证据。[固件接入](https://linx.qiniu.com/docs/xrobot/guide/xiaozhi-firmware)

### Inferences

**本轮证据链：** 浏览器现场真人麦克风 → 灵矽实时 WebSocket → MCP 工具调用 → 官方 robotd/MuJoCo → 仿真动作/接触/状态 → 工具回执 → 云端语音说明。界面明确标“仿真世界”，感知字段标“MuJoCo 状态”，音乐标“本地合成”；不伪称机载音频、摄像头或实体传感器。

**建议主线，约 3 分 40 秒：**

| 时间 | 台上行动 | 观众看到的证据 |
|---|---|---|

**一次实质开发迭代的收敛建议：**

1. 先用现场真人语音验收一条完整云端工具链与取消路径；不能只重放 WAV。
2. 做白名单对话微动作仲裁，视条件引入 `robot.look`；目标坐标来源明确为仿真对象状态。停止、显式动作优先。
3. 选择专注任务状态机作为主要新增；导演复用现有云工具与取消；踢球教练补状态查询和回合逻辑。十个场景是产品方案，不代表周二前全做。
4. 如增加点歌能力，需新增明确的曲目选择工具；现有 UI 曲目按钮不能称为灵矽语音选曲。歌曲仍由本地合成播放。
5. 验收旧动作/旧语音不复活、取消后不提醒、踢空不算进球、未知对象不编造；检查通过后冻结组合。

### Gaps

- “复刻一台并装入灵矽”的实体部分尚未完成，应在展示和报告中明确承认；本轮无法用仿真证明硬件、机载拾音、实体运动或功耗。
- 没有竞赛现场网络实测。云不可用时可以演已有本地模式，但必须显式降级说明，不能将本地文字结果、预录对话或本地合唱包装成实时灵矽。
