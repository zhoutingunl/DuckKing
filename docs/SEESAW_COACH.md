# 语音跷跷板教练

## 要让观众看懂的事

“我的动作也会改变环境。”圆盘关卡给定电机目标；这里的板面只有被动铰链，鸭子的接触力会改变倾角。橙色移动配重持续改变负载，迫使鸭子离开中心配平。向前走不等于直接到达目标：脚步先改变相对支点的位置，板面随之下沉，又改变下一步的支撑条件。

## 页面设计

- 沿用站点浅色背景与官方 MicroDuck 模型。配色：纸白 `#f5f6ef`、墨绿 `#243c36`、支点深灰 `#48544f`、前端青绿 `#477d79`、后端赭黄 `#bd8748`、失败棕红 `#a6533a`。
- 中文使用现有系统字体；标题、动作动词清晰有力；仿真读数使用等宽数字，图例与物理板面的两端同色。
- 首屏让跷跷板占主要面积，支点明确可见。前后是鸭子的世界固定初始朝向，不随相机旋转改变；避免用屏幕左右代替物理方向。
- 将“走动 → 相对支点的位置 → 板面倾角”作为同一条实时因果读数。曲线来自同一物理时钟，有限长度，页面不可见时减少渲染。
- 明示“本地实际物理”与“灵矽实连”，已训练、未训练和手动探索分别标注。失败不能表现为无提示冻结。

```text
语音跷跷板教练                         模式与简短口令
┌──── 回中站定规则 ────────┬──── 所选任务控制器 ────┐
│     被动板面 + 支点        │    相同初态，独立受力    │
└──────────────────────────┴──────────────────────┘
  本轮动作 → 支点位置 → 板面角度       开始 / 停止 / 重置
  同一时间轴上的真实测量曲线             连接灵矽、按住说话
  PPO训练记录、奖励函数、验收规则和限制
```

## 物理与学习边界

使用官方 MJCF 碰撞模型及冻结的 `velstand.onnx` 步态。任务策略输出有界前后速度；工程控制保持横向位置和初始朝向。MuJoCo 计算接触、重力与被动铰链响应。回合中不得直接改写鸭子或板面的位姿，不向板面添加控制器，不用动画替代失败。

验收以真实支撑、板面水平保持和有界动作判断，不能把压在限位上的板面算成功。训练、验证及最终测试的种子分离；网页只展示实际采集数据。第一版属于仿真任务策略，未证明可直接迁移实体机器人。

## 已实现的物理与控制规格

| 层 | 输入 → 输出 | 频率 / 限制 |
|---|---|---|
| 灵矽 / 本地按钮 | 开始、停止、状态、重置、探索 | 使用同一个房间后端；普通走路/踢球工具不向跷跷板房间开放 |
| 任务 PPO | 18 维真值观察 → 3 类动作 | 10 Hz；站定 0、前进 +0.25 m/s、后退 −0.35 m/s |
| 工程反馈 | 横向位置、朝向 → 横移/转向指令 | 横移限 ±0.06 m/s，转向限 ±0.8 rad/s；基线与 PPO 相同 |
| 官方步态 | 身体状态＋速度指令 → 14 关节 PD 目标 | 50 Hz，冻结 `velstand.onnx` |
| 真实接触 | 关节目标、重力、接触 → 下一物理状态 | MuJoCo 200 Hz；板面 1.0 × 0.44 × 0.03 m、1.5 kg |
| 移动配重 | 目标位置 → 有界滑轨驱动力 | 0.28 kg；幅度 0.28–0.32 m，周期 10–12 s；200 Hz 更新目标；kp=100、kv=6、力限 ±3 N |
| 被动板面 | 脚部接触力矩与配重经导轨传力 → 绕 Y 轴转动 | 支点高 0.23 m，铰链阻尼 10 N·m·s/rad，关节限位 ±0.105 rad（约 6°），没有板面电机和回正弹簧 |

首次准备时两侧暂停在同一初态；开始时采用同一个种子，改变起始侧、距支点 4.5–8.5 cm 的偏移、0.85–1.1 的摩擦系数，以及配重初始方向、幅度和周期。左右共享模型与串行 ONNX 会话，但有独立 `MjData`、步态历史和动作。每个任务 tick 先更新两侧，再公布快照。一侧提前失败后定格并显示实际原因，另一侧继续。左侧挑战使用“只回中心站定”规则，不再是原先的官方站定。两侧配重目标轨迹相同，实际位置各自由滑轨电机和物理约束求解；板角不跟踪预设轨迹。

页面曲线为同步采样的速度**指令**、实际前后位置、配重实际位置、实际倾角；附加接触力矩是 `mj_contactForce` 转换到世界坐标后，针对板面一侧求关于支点的 Y 轴力矩之和。它不是躯干距离乘总重量的近似值。正位置为绿色前端，正倾角为绿色前端下沉。各曲线单位分别列明，量程随数据扩展。

手动探索一次 1–3 秒（网页按钮为 2 秒），只对右侧发出走动指令，左侧保持站定并同步推进真实物理；可从当前状态连续探索，总仿真时间最多 18 秒，需重置才能重新开始。探索不计成功。停止会清除待执行速度并**暂停仿真**，没有把板面实际速度改成零；这与转盘的有驱动减速不同。

## 成功标准与奖励

标准回合为 18 秒。提前跌倒、身体触板、触地、脚部越界、连续超过 0.4 秒无支撑会失败。稳定条件为：倾角绝对值 <2°、角速度绝对值 <4°/s、至少一只脚有支撑。前 2 秒之后的 160 个任务 tick 中至少 70% 稳定，且最后连续 0.5 秒稳定，才算成功。成功不再要求躯干位于中心 3.5 cm 内。压在 ±6° 限位上不算成功。接触点采样不是碰撞次数。

当前契约 `seesaw-v3-counterweight` 的奖励：

- 水平：`2 exp(-(angle_deg / 3)²)`。
- 配平：`exp(-(net_gravity_torque_nm / 0.35)²)`。重力合力矩按鸭子总质量及实际子树质心、配重质量及实际质心计算。固定回中奖励已删除；这个力矩项属于明确的物理先验。
- 直立：`0.25 upright`。
- 抑制快速板面转动：`-0.1 min(abs(angular_speed_deg_s) / 12, 2)`。
- 走动成本：非零动作 `-0.06`；动作改变 `-0.03`。
- 在稳定条件下选择站定：`+0.25`。
- 提前失败或到时未达标：`-15`；成功：`+25`。

优化器使用原始奖励的 0.1 倍；页面与评估回报使用原始单位。奖励项可点击查看公式、系数与最新贡献。18 维输入依次为：归一化前后/横向位置、世界前后/横向速度、朝向、直立度、板角、板角速度、支撑比例、上一动作三维 one-hot、稳定保持时间与回合进度、配重位置 / 0.32 m、配重速度 / 0.25 m/s、重力合力矩 / 1 N·m、配重周期 / 12 s。前进/后退方向选择由新任务 PPO 学习；工程反馈与冻结步态属于先验，不宣传成从零学会走路。

配重反馈规则是 `error = net_gravity_torque_nm / (0.73724318 × 9.81) + 0.4 × angle_rad`，误差 >1.5 cm 则后退，<−1.5 cm 则前进，否则站定。另有回中规则：位置 >0.8 cm 则后退，<−0.8 cm 则前进，否则站定，完全忽略配重。两者都未经 PPO 训练，分别报告成绩；不保证 PPO 超过已知物理模型的人工反馈控制。

## 训练和网页接口

训练环境使用 [training/requirements.txt](../training/requirements.txt) 的独立 CPU 解释器。服务进程不需要安装 PyTorch，仅加载经过契约、物理模型 SHA-256、尺寸、步数和有限值校验的 JSON 网络。没有兼容且完成评估的工件时返回错误，不能自动改用规则。

```sh
# 已按平衡教练文档准备独立训练环境；从仓库根目录执行。
# 从静态板面策略迁移；省略 warm-start 则从随机任务策略开始。
PYTHONPATH=src .duckking/balance-venv/bin/python training/train_seesaw.py \
  --output .duckking/seesaw/my-run --steps 131072 --seed 42 \
  --warm-start training/seesaw_results/static-v2/policy.json

# 网页显示指定工件目录；服务重启后生效。
DUCKKING_SEESAW_ARTIFACTS=.duckking/seesaw/my-run \
  PYTHONPATH=src .venv/bin/python -m duckking.app --port 8765
```

输出目录必须尚不存在，避免覆盖历史记录。训练为单采样进程、单 Torch 线程；PPO 网络两个 64 维 tanh 隐藏层，离散分布；`n_steps=1024`、`batch_size=64`、`n_epochs=5`、学习率 0.0003、gamma 0.99、GAE lambda 0.95、entropy 0.01、clip 0.2。每 8192 环境步，在固定验证种子 20000–20019 上评估；预先约定连续两次 ≥18/20 才标记达到验证门槛。最终独立测试使用 30000–30099，官方站立、回中规则与配重反馈规则使用同一组种子。训练随机种子和环境种子区间另行记录。测试种子不用于选 checkpoint。

训练过程中 `report.json` 原子更新，网页每 5 秒读取真实记录。`policy.json` 是验证集成功率优先、回报次优选择的工件；`early.json` 为本轮开始时的策略。CLI 可用 `--warm-start` 从归档的 `seesaw-v2-settle` actor 迁移：保留原 14 个输入权重，新增 4 个配重观察列初始化为零；价值网络与优化器重新开始。旧 actor 来源步数为 49,152，模型哈希严格限定为已归档版本。这次物理模型、回合时长、奖励和成功条件都变了；记录源/目标模型哈希，明确标为跨任务迁移，不能叫同一实验继续训练或随机 0 步网络。Ctrl-C / SIGTERM 会保存取消状态；网页当前只展示记录，不开放浏览器启动 CPU 训练。

- `POST /api/seesaw/prepare?room=N`：准备独立房间；语音连接期间不能替换物理世界。
- `POST /api/seesaw/command?room=N`：`start / stop / reset / status / nudge`；参数按操作严格校验，拒绝无关参数和无界时长。
- `GET /api/seesaw/training`：当前公开训练记录，不含用户录音、设备身份或工件路径。
- 复用 `/api/scenes/state`、`/api/scenes/model.dkm.gz`、`scene-ws` 和 `scene-voice`。已有 HTTPS 网关可以继续转发这些路径，不新增端口或改 ai_gateway。
- 灵矽仅发现 `duck_seesaw`、`duck_stop`、`duck_get_status`，本地与云端都进入相同真实后端；重复 MCP 请求不重复启动。新一句话保留挑战，显式停止、断连和云端失败仍停止任务。

## 训练记录与历史隔离

本次独立测试：PPO **99/100**，回中规则 **0/100**，官方站定 **0/100**，人工配平反馈 **76/100**。PPO 平均绝对倾角 **0.443°**，平均水平时间占比 **98.15%**。本阶段第 49,152 步、约 **9 分 13 秒**达到预设验证门槛；完整 131,072 步及最终评估共约 **26 分 53 秒**。

当前移动配重版本的实际工件和评估放在 [training/seesaw_results](../training/seesaw_results/README.md)。静态板面的原始工件和报告归档在 `training/seesaw_results/static-v2/`；其 88/100 成绩不能当作移动配重版本成绩。模型哈希与控制契约不匹配时，服务器拒绝执行旧工件。

配重目标沿板面的 X 轴往返：`direction × amplitude × smoothstep(min(t/2,1)) × sin(2π × max(t−1,0)/period)`。它由真实滑动关节的位置执行器跟踪；仿真开始后不改写配重、板面或鸭子的位姿。配重质量的重力及惯性经过滑轨约束传给板面。页面的“重力合力矩”只表示重力项，不等于完整动态合力矩，也不等于脚部接触力矩或滑轨电机力矩。

训练选 checkpoint 只使用验证集，最终测试留出的 100 个环境种子不参与选择。墙钟计时从本阶段启动开始，包含采样与评估，不包括此前静态任务训练。仅用一个训练随机种子，不能将 100 个环境种子称为 100 次训练。

## 验证与限制

这是高阻尼、低倾角、单鸭的首版实验。已接入固定质量、动态位置配重；未接入双鸭、可变质量配重、实体机器人、摄像头感知或端到端关节强化学习。模拟可观测量不等同实体传感器可直接取得的量。浏览器可本地探索而不连接灵矽；云端模式仍需要该房间独立绑定及有效配置。新增工具的本地协议验证不能替代真实云端 STT/MCP/TTS 联调。

物理与取消测试在 `tests/test_seesaw.py`；前端结果语义、HTTP 接续和真实场景浏览器测试在 `frontend/tests/seesaw*` 与 `scene-state-feed.test.js`。CPU 墙钟时间包含实际运行负载下的采样与评估，不能当作独占机器或 Linux 服务器基准。训练成绩来自随包实际报告，不生成示意成功曲线。

滑轨位置执行器参考 [MuJoCo MJCF position actuator](https://mujoco.readthedocs.io/en/3.3.7/XMLreference.html#actuator-position)。模型与步态来自 Pollen Robotics 固定版本，许可及来源沿用 [THIRD_PARTY.md](../THIRD_PARTY.md)。接触力解释参考 [MuJoCo 3.3.7 API](https://mujoco.readthedocs.io/en/3.3.7/APIreference/APIfunctions.html#mj-contactforce)；PPO 实现使用 [SB3 2.4.1](https://stable-baselines3.readthedocs.io/en/v2.4.1/modules/ppo.html)。
独立训练验证（可选，需要训练解释器）：

```sh
PYTHONPATH=src .duckking/balance-venv/bin/python training/test_seesaw_trainer.py
```

它实际执行短程 PPO 更新，比较 SB3 与导出 JSON 的动作，核验续训时新增输入权重为零、策略步数保留来源，以及终止／奖励缩放／评估取消行为。
