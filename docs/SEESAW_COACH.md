# 语音跷跷板教练：用脚步控制自由配重

## 核心体验

“我的动作也会改变环境。”转盘由电机按给定节奏运行；这里板面与配重均无电机、无时间轨迹。鸭子走位改变接触力矩，板面倾斜，重力推动配重沿导轨滑动；配重位置变化又改变板面负载。任务是把橙色配重送回红色停靠区，然后反向调整、制动并停稳。

两侧从相同初态出发，独立计算接触和运动。左侧可选择回中站定规则或真人控制，右侧使用所选控制器。两侧配重轨迹的分岔正是动作改变环境的证据，不能强制同步它们的位置。没有运动电机或自动回中、磁吸、配重锁定。红色区只有可见标记，没有碰撞和控制力。

页面保留真实 MuJoCo、手动按钮和灵矽实连的区别。可先说“向后退，看看配重怎样滑”，再说“把配重送回红色区，再停稳”。实际云端语音仍需要独立房间配置；本地 MCP 测试不等于已完成云端 STT/MCP/TTS 联调。

## 页面与观众读数

- 左右对照：回中规则 / 右侧 PPO、早期策略、人工配平规则或手动探索。
- 首屏四步因果链：动作 → 鸭子位置 → 板面响应 → 配重滑动；显示实际接触力矩。
- 橙色块、导轨和红色双刻线沿用模型的几何，公开显示数据把停靠区绘为红色。双刻线之间 ±4 cm 指配重**中心**的接纳区，不要求整个块都装入标记内。
- 两侧分别显示配重中心位置。右侧另显示滑动速度、区内停稳时间、重力合力矩。
- 同一仿真时间轴上的指令、鸭子位置、配重位置、板角。配重/板角都叠加左侧虚线，配重图标出红色停靠带；曲线为实际状态，不能用指令推断已执行。
- 前后为世界固定的鸭子初始朝向，不随相机旋转改变。观察来自 MuJoCo 真值，不是摄像头。
- 页面保留训练曲线、奖励解释、实时输入、明确失败原因和无分数的手动探索。

## 物理与控制规格

| 层 | 输入 → 输出 | 频率 / 限制 |
|---|---|---|
| 灵矽 / 本地按钮 | 开始、停止、状态、重置、探索 | 同一个房间后端；跷跷板不开放普通踢球/走路工具 |
| 任务 PPO | 17 维真值观察 → 3 类动作 | 10 Hz；站定 0、前进 +0.25 m/s、后退 −0.35 m/s |
| 工程反馈 | 横向位置、朝向 → 横移/转向指令 | 横移限 ±0.06 m/s，转向限 ±0.8 rad/s；所有控制器相同 |
| 官方步态 | 身体状态＋速度指令 → 14 关节 PD 目标 | 50 Hz，冻结官方 `velstand.onnx` |
| 真实物理 | 关节控制、重力、接触 → 下一状态 | MuJoCo 200 Hz；官方 MJCF 全碰撞模型 |
| 被动板面 | 鸭脚接触及配重传力 → 绕 Y 轴转动 | 板 1.0×0.44×0.03 m、1.5 kg；支点高 0.23 m，阻尼 10 N·m·s/rad，限位 ±0.105 rad（约6°） |
| 自由配重 | 重力、惯性、导轨约束 → 沿板面 X 轴滑动 | 0.28 kg；限位 ±0.35 m，阻尼 1 N·s/m；无弹簧、无执行器 |

总共只有鸭子的 14 个执行器。回合中不改写鸭子、板面或配重位姿，不添加外力来安排演出。初始条件只在 reset 设置：鸭子距支点 ±4.5–8.5 cm，摩擦 0.85–1.1，配重在任一侧距中心 20–24 cm，初速度为零。相同种子可重复同一初态；种子不表示难度。

正位置为绿色前端，正板角表示绿色前端下沉。接触力矩来自 `mj_contactForce` 转到世界坐标后，针对板面一侧求关于支点 +Y 的力矩。重力合力矩使用鸭子实际子树质心和配重实际质心，只表示重力项，不等于完整动态合力矩或脚部接触力矩。

左右共享只读模型结构及串行 ONNX 会话，各有独立 `MjData` 和步态历史；两侧 reset 为同一种子时使用相同摩擦。每 tick 先计算两侧，再公布快照。一侧提前失败后定格说明原因，另一侧可继续。每房间后端独立，动作取消受房间所有权约束。

## 成功与奖励

回合 18 秒。跌倒、身体触板、触地、脚部越界或连续超过 0.4 秒无支撑会提前失败。最终成功须无提前失败，且**最后连续 1 秒**满足：

- 配重中心距离停靠中心 <4 cm；
- 配重速度绝对值 <2.5 cm/s；
- 板角绝对值 <2°、角速度绝对值 <4°/s；
- 至少一只脚支撑。

只回中心站定、板面水平、配重高速经过目标区，均不够。取消旧任务“70% 时间水平”的门槛，允许为了运输配重先倾斜。水平时间占比仍作为诊断量保留。

控制契约 `seesaw-v4-passive-docking` 的逐步奖励：

| 项 | 原始奖励 |
|---|---|
| 接近停靠区 | `4 exp(-(dock_error_m / 0.12)^2)` |
| 到站减速 | `exp(-(dock_error_m / 0.06)^2 - (weight_velocity_m_s / 0.05)^2)` |
| 温和板角 | `0.5 exp(-(angle_deg / 3)^2)` |
| 配平 | `exp(-(net_gravity_torque_nm / 0.35)^2)` |
| 直立 | `0.25 upright` |
| 抑制快速转板 | `-0.1 min(abs(angular_speed_deg_s) / 12, 2)` |
| 走动 / 切换成本 | 非零动作 `-0.06`，动作改变 `-0.03` |
| 停靠时站定 | 满足全部停靠条件且选择站定 `+0.25` |
| 终局 | 成功 `+25`；提前失败或到时未达标 `-15` |

奖励是明确的任务和物理先验，不能宣传为从零发现物理。优化器使用原始奖励的 0.1 倍，网页显示原始单位。每项可点击查看系数、说明及实时贡献。

17 个观察：前后/横向位置、世界前后/横向速度、朝向、直立度、板角、板角速度、支撑比例、上一动作三维 one-hot、区内停稳时间 /1 s（截断到1）、回合进度、配重位置 /0.32 m、配重速度 /0.25 m/s、重力合力矩 /1 N·m。旧版“配重周期”输入已删除，因为现在没有周期控制。

人工配平规则保持原式 `error = net_gravity_torque_nm / (0.73724318 × 9.81) + 0.4 × angle_rad`：超过 ±1.5 cm 则反向走，否则站定；它不规划配重到站。回中规则只让鸭子在 ±0.8 cm 内站定，忽略配重。两种规则和官方站定均不叫 PPO，并与 PPO 使用同一组测试种子单独报告。它们不是经过调优的最强停靠控制器，不能据此声称 PPO 优于所有传统控制方法。

## 有界动作、接口和暂停

手动探索一次 1–3 秒（网页按钮2秒），右侧听用户指挥，左侧站定同步推进；可以连续探索，累计最多18秒。探索不计成功。停止清除待执行指令并**暂停仿真**，不把真实板面/配重速度归零，也不宣称已自然停稳。重置恢复同一初态。失败、取消、过时请求、非法策略都不能静默改为预览或规则。

- `POST /api/seesaw/prepare?room=N`：准备独立房间，语音连接期间不能替换世界。
- `POST /api/seesaw/command?room=N`：`start / stop / reset / status / nudge`，严格校验参数。
- `GET /api/seesaw/training`：公开真实训练记录，无设备身份、用户音频或本机路径。
- 复用 `api/scenes/state`、`api/scenes/model.dkm.gz`、`scene-ws`、`scene-voice`，无需改 ai_gateway。
- 灵矽仅发现 `duck_seesaw`、`duck_stop`、`duck_get_status`；重复请求不重复启动；新一句话保留挑战，显式停止、断连或云端失败会停止任务。

## 真人与 AI PK

从顶部“训练新动作”进入 `training.html`，选择转盘或跷跷板。选择页不加载模型或启动物理。跷跷板选择“真人 vs AI”，开始后左侧听用户指挥，右侧继续所选 PPO。灵矽调用 `duck_seesaw` 的 `start mode=duel` 开始；PK 中 `nudge forward/backward/hold` 仅更新左侧的有界指令，不重置、暂停或替换右侧任务。可说“左边前进两秒”“后退一秒”“站定”；按钮每次2秒。

时长按仿真时间1–3秒，新指令替换旧指令，结束自动给站定指令；站定不保证瞬间停稳。重复 MCP 请求不能延长指令。语音识别期间比赛继续，未扣除网络／理解延迟，因此是实际交互体验对照，不是排除延迟后的算法竞赛。两侧使用同一18秒仿真时钟、初态和成功标准；一侧提前失败则冻结该侧，另一侧继续。全球停止或语音断连会暂停两侧，不能继续未完成的PK，需重开。默认 `mode=compare` 保留回中规则对照；运行中的规则对照拒绝插入手动探索。

红色仅为展示调整：`SeesawBackend` 修改导出几何的RGBA，并以 `-red1` 更新视觉缓存键。训练模型MJCF、物理哈希、观察与奖励保持原样；未重新训练，也未把原成绩当作一次新评估。前端只接受已知显示版本与完全匹配的物理哈希。

## CPU 训练、工件与复现

使用独立 CPU 训练解释器（依赖见 `training/requirements.txt`），服务仅加载经过契约、模型 SHA-256、网络形状和有限值检查的 JSON 数值网络。没有匹配且评估完成的工件时，拒绝 PPO 执行；可明确选择规则或手动模式，不自动替代。

```sh
PYTHONPATH=src .duckking/balance-venv/bin/python training/train_seesaw.py \
  --output .duckking/seesaw/passive-reproduce --steps 131072 --seed 42 \
  --warm-start training/seesaw_results/driven-v3/policy.json
```

输出目录须不存在。一个采样进程、一个 Torch 线程；两层64维 tanh，3类离散动作；`n_steps=1024, batch_size=64, n_epochs=5, learning_rate=0.0003, gamma=0.99, gae_lambda=0.95, ent_coef=0.01, clip_range=0.2`。

此次从有驱动配重 v3 actor 迁移，保留前17个输入权重，删除周期列；“hold”改为停靠保持 /1秒，critic 和优化器重新初始化。源 actor 包含180,224步来源（静态49,152＋有驱动131,072），这不是本轮新采样量，也不是全部试验成本。也支持显式从归档v2迁移：保留14列，新3列为零。来源模型哈希限定到归档版本。

验证每8192步进行一次，种子20000–20019；连续两次≥18/20才记录达到预设验证门槛。按验证成功率、其次平均回报选择 checkpoint。最终100个未见种子30000–30099不参与选策略。训练种子42对应环境种子从520001开始。一个训练种子不能称作100次独立训练。

报告原子写入，网页每5秒读取实际进度。CPU墙钟时间含本阶段采样和评估，也包含同时开发的资源竞争；不含历史阶段训练，不是独占机器或服务器基准。Ctrl-C/SIGTERM记录取消，网页不提供启动CPU训练按钮。

本轮独立100种子测试：PPO **98/100**；回中、官方站定、仅配平板面三种规则各 **0/100**。第98,304步（26分37秒）达到验证门槛，完整131,072步及最终评估共36分45秒。PPO末尾距停靠中心平均1.58 cm；两次未停靠失败保留在报告中。

当前工件与最终结果见 [training/seesaw_results](../training/seesaw_results/README.md)。历史静态v2与有驱动v3分别保存在 `static-v2/`、`driven-v3/`；旧版88/100、99/100均不能作为当前自由配重停靠成绩。

## 验证和边界

物理测试检验板面/配重无执行器、无外力、同初态不同动作导致不同配重轨迹、只回中失败、水平但未停靠失败、高速穿越不算成功，以及停止、重置、隔离、协议和失败处理。浏览器检查真模型、轨迹、移动端、相机、停止和结果提示。训练解释器测试实际短程PPO更新/JSON推理一致性、迁移来源、奖励缩放和取消。工件哈希绑定原始策略、报告和环境；回放检验相同运行环境内可重复及成功条件。macOS 与 Linux 的闭环接触轨迹和离散策略决策可能分岔：Linux CI 中种子30018成功，而原macOS报告为未停靠，原始结果保持不变。98/100只属于记录的macOS实验，不是Linux或每次在线运行的成绩保证。

页面显示的是仿真时间；CPU训练或并行浏览器渲染占用资源时，18秒仿真可能需要更长墙钟时间。开发模式单独复测四项通过；训练并行和同时运行多个测试浏览器时曾触发墙钟超时，不能据此宣称实时性能有保证。

这是固定质量、高阻尼、小倾角、导轨配重的仿真实验；未证明实体迁移、未知质量/摩擦的泛化、摄像头感知或端到端关节学习。自由滑块不是自由滚动球；它受导轨约束但没有位置控制器。
