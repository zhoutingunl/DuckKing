## 0. 三条决定性情报

重读官方文档后才发现的三条，直接决定排序与排期：

| 发现 | 原文依据 | 影响 |
|---|---|---|
| **灵矽音色可在会话内切换**，且带 `pitch` / `emotion` / `volume` / `speed` | 灵矽《智能体与音色切换》：`listen` 消息里带 `agent_params.voice.id`；Header 里的音色切换已废弃 | "现场变声、变情绪"低成本记忆点；不必为换音色重建连接 |
| **智能体切换 = 握手 Header `X-Agent-ID`** | 同上 | "换脑子"只需改一个 Header；`onboarding.py` 已有智能体创建/列表/提示词回读校验/设备绑定全套 → 极便宜 |
| **音色克隆训练样本必须是公网 URL，训练要几分钟到十几分钟** | 灵矽《音色克隆API》`PUT /v1/voice-clones/{id}` body `key` 为音频 URL；建议 20–30 秒清晰音频 | **必须预训练**，周一一早就起跑，不能留到演示当天 |

排除性发现：官方 `sounds/` 目录只有代码与谱面，**没有现成音频资产**——官方声库按 SoC 序列号运行时生成（`sounds ensure-bank`）。"克隆官方鸭子的真实声库"拿不到素材，只能克隆**我们自己的鸭子声线样本**，台上必须说清。

主轴：**评委第一次看到时的那 0.5 秒反应强度**。
第二轴：新颖（不是"语音遥控器"的常规解法）。第三轴：抗现场故障。第四轴：已有能力覆盖度。

## 3. 逐条设计

### 第 1 名 ·《它终于用鸭子的声音说话了》★ 需新开发

| | |
|---|---|
| **一句话** | 所有人都在演示"机器人用助手的声音说话"。我们让它**用鸭子的声音说话**——这条嗓子是克隆出来的。 |
| **现场怎么演** | ① 预训练阶段：把我们为这只鸭子设计的声线样本（复用 `scripts/build_demo_audio.py` 的小鸭音色管线）做成 20–30 秒清晰音频，放到公网 HTTPS 路径 → 调用灵矽 `POST /v1/voice-clones` 建栏位 → `PUT /v1/voice-clones/{id}` 训练 → 轮询到 `Success`。<br>② 演示阶段：鸭子先用默认音色说一句；接着一条 `listen` 消息带 `agent_params.voice.id = <克隆音色>`，**同一会话内**换成鸭子的嗓子再说一句。<br>③ 二次冲击：现场再调 `pitch`（0.5–2.0）与 `emotion`，让评委**亲手把鸭子的声音拧高、拧低、拧凶**。 |
| **为什么难忘** | 唯一一个会让评委散场后还在讨论的瞬间。它同时把"灵矽"从语音识别器还原成了**声音身份引擎**——而身份正是官方 MicroDuck 自己的设计（`sounds ensure-bank`：每只鸭的声库由它的 SoC 序列号生成，*"a voice that is only its own"*）。 |
| **需要开发** | ① 音色克隆客户端（`xrobo.qiniu.com`，Bearer token，档位 `free`/`lite`/`pro`，`403` 表示该档位无额度）；② 会话内音色切换（`voice.py` 的 `listen` 消息加 `agent_params`）；③ 前端控件与状态展示；④ 验证：TTS 实际输出必须是克隆音色，要留试听记录 |
| **诚实边界** | 训练样本是**我们合成的鸭子声线**，不是官方 voice bank 的真实音频（官方资产不在仓库里）；训练耗时 10 分钟量级，**演示当天只演示切换，不演示训练**；`pitch`/`emotion` 是 **TTS 参数**，不是情绪识别；音色切换只改 TTS，**不切智能体、不改 STT** |
| **降级链** | 完整版 → **A**：不克隆，用灵矽现有音色 + `pitch`/`emotion` 现场"调出鸭子的声音"（零开发，记忆点保留七成）→ **B**：只讲机制 + 播放预录的克隆音色对比（明确标注"预先训练的克隆结果"） |

### 第 2 名 ·《拔网线演出》★ 已可演

| | |
|---|---|
| **一句话** | 拔掉网线，鸭子照样听懂你说话。 |
| **现场怎么演** | 断开 Wi-Fi / 拔网线 → 说"向左转""跳个闪身步" → 鸭子照样动。复网后同一句话继续可用。 |
| **为什么难忘** | 全场大部分组在演示"我接了个云端大模型"。**拔网线**是唯一能证明"这是硬件智能体、不是云玩偶"的动作，直接回答赛题里"智能硬件"四个字。 |
| **已有能力** | `hybrid_voice.py` 本地优先路由；`asr_service.py` 隔离的 loopback ASR worker（SenseVoiceSmall INT8，127.0.0.1:8768）；`local_commands.py` 整句文法 |
| **实测数据** | 合成三动作录音 **409 ms**，否定句 **139 ms**，模型初始化 1640 ms；两个独立房间松手至首个动作受理 **749 ms / 1215 ms**（含共享 worker 排队）。合成样本，不代表手机录音准确率。 |
| **诚实边界** | 本地只认 **35 种命令 / 121 个说法**：整句匹配、全有或全无，无子串命中；单次最多 6 个动作、总时长 ≤20 秒。**不是通用理解**——问句、条件句、否定句**故意**不匹配，会带着同一段原始录音一次交接给灵矽。 |
| **风险** | 断网会牵连云端戏 → 排在云端戏之后，或让机器走独立热点 |

## 4. 两天冲刺排期（→ 周二 09:00）

单人有效工时约 14–16 小时（TEAM.md 目前只有 @zhoutingunl 一人确认）。**关键路径是音色克隆**，因为训练异步 + 耗时 + 可能重训。

## 8. 诚实边界总表（上台前逐条过一遍）

1. 音色克隆样本是**我们合成的鸭子声线**，不是官方 voice bank 真实音频（官方 `sounds/` 只有代码与谱面）。
2. 音色训练 10 分钟量级 → **预训练**；现场只演示切换，不演示训练。
3. `pitch` / `emotion` 是 **TTS 参数**，不是情绪识别。
4. 音色切换只改 TTS，**不切智能体、不改 STT**；智能体切换要**重连**，有握手开销。
5. 本地只认 **35 种命令 / 121 个说法**，整句全有或全无；问句、条件句、否定句**故意**走云端。
6. 即时编舞**不是新策略、不是新技能**，是把描述翻译成有界高层意图。
7. 官方 **BLE chorale 真同步**（无共享时钟、约 25 拍相位平均、±20ms）**仍未实现**；当前四声部是单个 AudioContext 本地合成，未移植官方音色合成器。
8. `vetbook` 生命记录自述未实现，**不编造人生**。
9. 桌上跌落有已知物理失败率；失败不记为成功。
10. 触球数是每物理步接触点累计，不等于碰撞次数；受理时间 ≠ 首帧物理动作时间。
11. 两间房云端响应不同，**不能保证同步起拍**。
12. 全部是**仿真**，不是实体机器人；未做实机验收。
13. 官方模型、策略与外观归 Pollen Robotics；灵矽能力归七牛云。见 `THIRD_PARTY.md`。
