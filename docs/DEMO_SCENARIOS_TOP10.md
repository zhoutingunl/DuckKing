## 0. 一句话与核心策略

**让评委自己把鸭子教会。**

前两版都在优化"我们演什么"。v3 换了个思路：**仓库里已经有比任何剧本都强的能力——
真人麦克风、现场可玩、每一步都有工具结果。** 所以主秀不再是我们演示，而是评委上手，
而我们负责在旁边递证据。

两条硬策略：

1. **视频做证据片，工坊做现场片。** 4 分 02 秒成片回答"真不真"，剪辑到 90 秒开场；
   之后 4 分钟全部是评委自己说话、鸭子自己反应，回答"好不好玩"。
2. **主动讲限制。** 唯一没能演成的（音色克隆额度三档为零）**在台上说**，不藏。

## 2. 实测数据（公网 YZH737，真实灵矽，同一段合成口令，各 10 轮，分四批交错）

| 路径与阶段 | 均值 | P50 | P90 | P95 |
|---|---:|---:|---:|---:|
| 本地 · 识别返回 | 284.3 | 261 | 329 | 443 |
| 本地 · 动作受理 | 285.7 | **262** | 330 | 446 |
| 灵矽 · 识别返回 | 426.9 | 406 | 470 | 588 |
| 灵矽 · 动作受理 | 1660.4 | **1664** | 1813 | 1879 |

**这张表是 v3 最重要的资产**：识别只差 1.6 倍，**动作受理差 6.4 倍**——
本地省掉的是"理解→决策→工具调用"这一整轮云端往返。

口径（必须照搬，不许简化）：起点是服务端收到结束录音，终点分别是首条非空识别文本或动作受理；
不含麦克风、扬声器、首帧显示与实际物理动作完成；10 个样本的 P95 是本组最大值，**不代表稳定性能**。

**答辩点播备用**：《千里点将》（评委手机走公网 HTTPS 指挥）、《四人四鸭同堂》（多评委各自申领一间动态房间同时指挥——零开发，但**新房间云端设备需管理员预绑定，且 ASR worker 单线程**，第二房实测排队至 1215ms，**两房本地、两房云端错峰**，勿四房同时抢识别）、《轮滑出场》（官方轮滑技能）、《四鸭失足记》（自动剧场第 11 幕，真跌落 + 自嘲）、《它拒绝了你》（摇头/歪头/哈欠/自然待机）。

> **建议追加的一个小开发（约 2–3 小时，性价比最高）**：**暗号 × 断网闭环**。
> 现状是 `duck_recipe` 的暗号存在服务端 `data_dir`，而本地路由只认静态 121 说法——**教学与边缘未打通**。
> 做法：`hybrid_voice` 拿到 ASR 文本后**先查已确认暗号表**，再走静态文法。
> 现场效果：教它"『下班』= 摇头坐下" → 确认 → **当场拔网线** → 喊"下班" → 照样执行。
> 这一步把第 1 名和第 2 名**焊成一句话**：*教一次，终身带电；断网也认。* 两端代码均现成，是本轮最值得做的增量。

**降为讲机制不实演**：官方 BLE 合唱真同步、ToF  theremin、实体硬件对照、`vetbook` 人生记录。

## 4. 五分钟主秀

| 时间 | 段落 | 内容 | 证据 |
|---|---|---|---|
| **0:00–0:50** | 证据片 | **新录 90 秒**（覆盖 studio：暗号确认、指挥换队、叼着续送）+ 4:02 成片里的物理高光剪辑（真实触球、嘴部搬运、桌上跌落恢复、四鸭坐站轮唱、延迟实测） | 视频自带 SHA-256 与来源标注；studio 短片冻结前挂同一 Release，答辩可二选一播放 |
| **0:50–1:30** | 第 1 名《我教你一个暗号》 | 评委现场说「『开饭』就是先点头再抖毛」→ 工具回草稿 → 下一轮说「开饭」→ 鸭子照做 → 再断开重连说一次，它还记得 | `duck_recipe` draft/confirm/run + 私有落盘 |
| **1:30–2:10** | 第 2 名《两条路》 | ① 同一句各 10 轮，投屏本地 262ms vs 灵矽 1664ms；② **当场拔网线**再说一次，它照样动 | `experience` 实时聚合 + 本地 ASR |
| **2:10–2:50** | 第 3+4 名《鸭王说》《换班不换鸭》 | 评委说"点头"→ 不动；说"鸭王说点头"→ 点头。切到严教练 / 摸鱼搭子，同一问题两个答案 | `duck_game` 前缀校验 + `X-Agent-ID` 重连 |
| **2:50–3:35** | 第 5 名《评委当指挥》 | "C 先唱，再 A" → 唱完 A 之前说"下一位换 B" → C→B 生效，当前歌手唱完坐回再交接 | `duck_conduct` queue 替换 |
| **3:35–4:15** | 第 6 名《物理当教练》 | "先看看别动"（只读）→ "摆到右脚前" → "踢球" → 公示真实触球数与球位移 | `duck_coach` observe/prepare/kick |
| **4:15–5:00** | 收尾 | 诚实边界 + **主动说明音色克隆额度为零** + 后续路线 | 双证据：`statistics.html`（本进程逐轮）+ `experience.html`（跨重启长期曲线）——"今天的每一轮，以及这台机器这些天的每一天" |

**主秀设计原则**：
- 每个互动项**都要评委开口**，演示者只递工具与证据；
- 每个互动项**结束前必须出示一次物理结果或工具结果**，不靠口头"完成了"；
- 任何一项失败就**跳过**，不圆场。

## 7. 诚实边界总表（上台前逐条过一遍）

1. **音色克隆没有成功**：账号 free/lite/pro 三档额度均为零，未发起训练、无克隆成功记录。现场演的是**实时调声**（`pitch`/`emotion`），不是克隆音色。
2. 三个试听样本是 macOS Eddy 中文合成 + 离线滤波的**训练素材**，不是克隆后的声音。
3. 暗号/配方是**私有持久化的有界动作表**，不是学到的新策略、新控制方法或新模型能力。
4. 临场导演是 1–6 步**已有**动作的重排，不是现场生成新动作。
5. 头部注视是**固定方向的限幅轨迹**，不是人脸跟踪、不是声源定位、不是新增视觉能力。
6. 鸭王说是按**本轮识别原话**检查前缀，不是说话人身份认证；换角色是握手 `X-Agent-ID` 的**页面控件**操作，需要重连，**不声称跨智能体会话记忆迁移**。
7. 四鸭合唱只用**本地《欢乐颂》8 秒短句**、浏览器本地合成，**不是云端生成音乐，也不是 BLE 同步**。
8. 延迟口径：起点是服务端收到结束录音，终点是识别文本或动作受理；不含麦克风、扬声器、首帧显示与实际物理动作完成；10 样本的 P95 是本组最大值，不代表稳定性能。
9. 浏览器与服务器是**两组独立观测**，不能相加当用户数，也不能相减估网络耗时。
10. 触球数是**每物理步接触点累计**，不等于碰撞次数；受理时间 ≠ 首帧物理动作时间。
11. 桌上跌落有已知物理失败率（曾捕获 `table_show=failed`）；失败不记成功。
12. 嘴巴搬运仅固定轻棒与初始布置，属实验性接触模型；不是任意物体抓取。
13. 全部是**仿真**，未做实机验收；官方模型、策略与外观归 Pollen Robotics，音乐原权利归原权利方。
14. 真人麦克风准确率尚未验收（现有记录为系统合成语音）；台上出现识别偏差要如实归因，不赖给模型。

| 头部注视（配方里的定向步骤） | `robot.look`（duck-ipc-proto `LookParams`） | 躯干坐标系固定目标点，不是人脸跟踪 |
| 自然待机、歪头、哈欠 | `idle_head.rs` / 官方 idle 行为 | 本地表情编排，不是视觉识别 |
| 四鸭合唱与队列 | 官方 `robotctl chorale` 的声部与席位规则 | 本地《欢乐颂》8 秒短句 + 单 AudioContext，**未做 BLE 同步与 ±20ms 验收** |
| 嘴部搬运 | 官方 beak 接触与开闭角度 | 实验性近似接触模型，非官方标定 |
| 《欢乐颂》谱面 | 官方 `wistful.duckscore` / 公共领域 SATB | 本地合成，**不是云端生成** |
| 轮滑 | 官方 `robot.setMode roller`（cheatsheet：Put wheels on） | 官方轮滑**技能**的仿真，非 roller 驱动策略复刻 |
| 坐下 / 站起 | 官方 sitstand 策略 | 确认接触支撑后才报完成 |
| 前滚翻、啄取、踢球 | 官方 `roulade` / `ground_pick` / `ball_kick_left`/`_right` ONNX | 官方 MJCF + 官方 ONNX 策略，进程内 MuJoCo CPU |
| 摔倒后自行站起 | 官方 `fallen` / `fall_recover` | 仿真侧行为，未做实机跌落测试 |
| 语音与音色 | 灵矽端侧 MCP / 会话内 `agent_params.voice` | 本地优先 + 一次交接；**克隆额度为零，演的是实时调声** |
| 身体所有权 | 官方 `robotd` JSON-RPC 2.0 over Unix socket（NDJSON） | 官方适配器路径；单写者、安全权威在 robotd |

> 一句话收束：**我们复刻的是官方 MicroDuck 的策略栈、协议栈与声音身份设计，接的是灵矽的大脑；
> 我们自己的原创是场景编排、边缘路由、工坊交互与验收体系。**（见 [THIRD_PARTY.md](../THIRD_PARTY.md)）
