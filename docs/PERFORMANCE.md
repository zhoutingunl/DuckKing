# 汇报现场容量实测（2026-11-02）

当前适合采用 **100 人访问、20–24 人一批独立语音体验、1–2 个重物理演示房间** 的组织方式。100 个共享状态订阅通过，不等于支持 100 个独立操作房间。当前没有自动排队或只读观众席；房间占满后新用户会看到容量提示。建议每批约 60–90 秒，体验结束关闭页面释放房间，100 人分 4–5 批参与。

部署应用为 `3f943bf26a08bc9b719bb9af929b4d328aeccbb6`（`deploy-yzh737-20261102T065603Z`）。此次未替换应用发布包；只增加主机运行配置、为房间 11–32 初始化独立私有设备，并运行可重复的压测。未复制其他房间设备身份，未放宽物理成功条件。

## 硬件与已生效配置

YZH737：双路 Xeon E5-2630 v4 2.20GHz，20 物理核／40 逻辑 CPU；系统可见 125 GiB 内存。计算使用 CPU，网页三维渲染在浏览器。检查时约 100 GiB 内存可用，主机同时运行其他业务。

主服务通过 [主机覆盖配置](../deploy/duckking-audience.conf.example) 调整为 CPUQuota=1200%、MemoryMax=32G、TasksMax=256；轻量房间 32、物理房间准入 4、空闲回收 60 秒。基础 unit 的默认值不变。该配置不等于每类场景都能稳定运行 4 路：四鸭桌上演出实测 4 路已经过慢，因此现场应限定重场景参与人数。ASR 保持独立的 1 CPU 时间配额、1 GiB 内存、单推理线程。

`CPUQuota=1200%` 是相当于 12 个逻辑 CPU 的时间上限，不是独占 12 核。普通物理场景的同步 tick 位于单个服务事件循环，增加配额不会把它自动拆成多个进程。

## 公网访问与首屏

| 测试 | 实测结果 | 解释 |
|---|---|---|
| 100 个共享预览状态连接，20 秒 | 100/100 保持；状态间隔 P95 110 ms；健康接口 P95 421 ms | 协议客户端，不执行 100 份浏览器渲染 |
| 当前配额下，100 个客户端同时下载首屏与模型 | 100/100 完成；总约 424 MB；完成时间 P50 70.1 s、P95 82.7 s；健康探针 2 次超时 | 操作端电脑经过公网 OR；负载生成器 CPU 约 21%，公网链路明显影响结果 |
| 单个真实 Chrome 冷启动 | 桌面约 1.85 s、390px 窄屏约 1.61 s；点头完成，无页面异常 | 在语音并发期间测量；窄屏仍是桌面硬件，不代表实际手机 |
| 服务器本机 100 客户端下载 | 100/100，P95 13.1 s | 绕过公网；生成器也可能成为限制，不是服务容量上限 |

早期旧配额／自动解压客户端测试有 15 个资源请求失败，保留在 `public.jsonl`，没有把失败计为成功。后来同时改变了主机配额与客户端读取方式，不能将全部差异归因于加 CPU。服务器经 OR 的对照测试全部完成，但与另一轮 20 客户端请求重叠，且生成器 CPU 接近 100%，不能作为独立容量结论。

**现场不宜让 100 人同时冷启动大模型。** 每人首屏约 4.24 MB，100 人合计约 424 MB。建议提前发链接、分批加载；要进一步改善，需要静态资源 CDN／边缘缓存、渐进模型加载等措施。现场 WiFi、NAT 和出口带宽仍需单独验收。前端模型下载有总超时，协议客户端下载完成不保证所有浏览器都能在同样耗时下显示模型。

## 真实灵矽并发

所有录音为仓库公开的系统合成中文 WAV，按真实时间发送 PCM；识别和返回音频来自真实灵矽。成功要求收到非空识别、非零音频和正常回复结束；没有把握手当作推理成功，也没有进行失败语音重放。

| 同时说话路数 | 实测轮次 | 成功 | 松手至首段音频 P95 |
|---|---:|---:|---:|
| 2 | 2 | 4/4 | 4.27 s |
| 4 | 2 | 8/8 | 4.24 s |
| 7 | 2 | 14/14 | 4.37 s |
| 16 | 2 | 32/32 | 4.64 s |
| 20 | 3 | 60/60 | 4.70 s |
| 28 | 3 | 81/84 | 5.14 s（成功样本） |

28 路均建立真实云端连接；第三轮有 3 路在已识别后未收到音频，约 25 秒失败。不能断言失败就是官方硬性并发限额。28 路来自请求 32 路时可用的空闲房间，其余房间由现有页面和独立浏览器验证占用；应用侧 409 与云端配额拒绝不同。

平台资源包 API 返回的是用量／余额，未提供本次账户的明确并发上限；已验证连接下界和实际成功率不能冒充合同配额。计费与结算规则参考 [官方说明](https://linx.qiniu.com/docs/xrobot/billing/resource-usage-billing)。本次验证接收了真实音频，但不是所有手机扬声器／现场麦克风噪声的验收。

## 物理场景分档

测试在 YZH737 的独立 loopback 服务执行，使用与生产相同的真实 MuJoCo、ONNX 和发布版本。扩容组限额为 12 CPU 时间配额、32 GiB；每档测量 45 秒。通过标准为有效仿真时间／墙钟时间 RTF ≥0.90，状态间隔 P95 <150 ms，健康接口 P95 <500 ms、零错误，并且没有动作失败。

| 场景 | 已通过档位 | 已失败档位 | 主要现象 |
|---|---|---|---|
| 动作练习场 | 1、2、4、8 房间 | 12 房间 | 8 房间 RTF约0.989；12房间约0.598，进程约占满一个逻辑 CPU |
| 四鸭桌上演出 | 1、2 房间 | 4 房间 | 2房间完成真实跌落／恢复验证；4房间约0.506倍速并触发过慢保护 |
| 平衡对照 | 1、2、4 房间 | 8 房间 | 4房间约0.992；8房间约0.533倍速 |
| 跷跷板对照 | 1、2、4 房间 | 8 房间 | 4房间约0.942；8房间约0.800倍速 |

这些是离散测试档位，不是证明所有中间人数都失败。平衡／跷跷板的通过表示推进与状态响应符合性能阈值，不表示每局任务都获胜。

旧 4 CPU／8 GiB 限额下，6 个练习场房间可实时运行；准备第 8 个时测试实例被其内存 cgroup OOM 杀死，主生产服务未因此退出。扩容后内存问题解除，但普通场景的单进程串行推进仍是瓶颈。冷初始化还会造成其他房间短暂变慢，正式演示应提前加载选定场景。

## 更接近现场的混合负载

| 组合 | 实测结果 |
|---|---|
| 100 个共享预览状态订阅＋20 路云语音＋2 个练习场／1 个桌上演出 | 状态连接75秒100/100；语音3轮60/60；首音频P95 5.42s；物理RTF约0.936；全部测试动作完成 |
| 100 个共享预览状态订阅＋24 路云语音＋1 个练习场／1 个桌上演出 | 状态连接120秒100/100；语音3轮72/72；首音频P95 5.39s；健康接口P95 262ms；物理RTF约0.949；动作完成，桌上演出verified=true |

第二组预览状态间隔 P95 84 ms；物理状态间隔 P95 分别约 227 ms、322 ms，桌上单次最大间隔约 1.65 秒。因此可以报告“连接与动作完成”，**不能报告“100 人各自进行物理体验且完全无卡顿”**。物理状态采用一帧一确认，公网 RTT、渲染和序列化共同影响更新频率；高质量展示宜由主持人控制重场景，大屏展示，观众以独立语音／动画体验为主。

## 离线 ASR

真实 CPU 推理：单请求约 635 ms；两个同时请求约 524／1009 ms。4 个同时请求仅 2 个返回 200、另 2 个返回 503；8 个同时请求仅 2 个成功、6 个返回 503。这符合单线程、最多两个未完成任务的实现。现场多人同时说话建议使用灵矽模式，不能把本地优先理解为支持几十路本地推理。

## 复现与证据

原始脱敏结果与测试边界见 [2026-11-02 证据目录](performance/2026-11-02/) 及 [method.json](performance/2026-11-02/method.json)。没有保存凭证、设备身份、录音或返回音频。采样器对缺少真实仿真时钟的响应显式失败；最初读取错误层级产生的零速结果已作废。长时间测试中回收空闲房间造成的 404 不是容量上限，已在补充 RL 测试中重新创建房间复测。

```sh
# 实际公网订阅与冷加载；只测试空闲房间
python scripts/benchmark_audience.py public --url https://duck.qbox.net \
  --output /tmp/public.jsonl --counts 10 50 100 --duration 20 --cold 100

# 真实灵矽调用，会消耗当前账户资源；不会重放失败录音
python scripts/benchmark_audience.py cloud --url https://duck.qbox.net \
  --output /tmp/cloud.jsonl --clients 20 --rounds 3

# 混合压测，只操作自动领取的空闲测试房间
python scripts/benchmark_mixed.py --url https://duck.qbox.net \
  --output /tmp/mixed.jsonl --cloud 24 --scenes skills table --duration 120
```

`benchmark_physics.py` 仅允许专用 `127.0.0.1:18765` 实例，应配置独立数据目录、无云端凭据和明确 CPU／内存上限；不能指向生产房间。完成后关闭瞬时服务并保存结果。`frontend/scripts/benchmark-browser.mjs` 使用 Playwright 验证单浏览器实际显示与操作，输出位置通过 `DUCKKING_BENCH_OUTPUT` 指定。
