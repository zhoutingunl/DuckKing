1. 这份清单怎么读：三条排序标准

一句话目标：让观众在三十秒内看明白"这只鸭子在学一件官方做不到的事"， 同时让懂行的人在三十秒内看明白"这背后是 RL 的哪个概念"。

排序不是按技术含量排的，而是按下面三条依次权衡：

标准含义为什么排在这个位置
① 观众看懂度不解释算法也能看懂输赢 放在第一位：竞赛现场只有几十秒，解释成本必须最低。球进没进门、谁先到终点，一眼就有答案。
② 教学价值能不能顺带讲清一个 RL 概念 第二优先。同一个玩法如果能带出一个算法点（探索、多智能体、层次…），价值远高于纯炫技。
③ 可交付性用现有底座能不能真做出来 第三优先但不是可忽略：做不出来的场景再好看也不该上台。每一项都标了工作量与主要风险。
必须先说清的一条红线：这份清单是展示优先级，不是成功率预测，也不是工程排期承诺。 文中不会出现"这个能到 90%"这种话——因为一个都还没跑。 仓库里唯一真正跑出数字的是转盘平衡 PPO（L1 100/100、L2 89/100、L3 59/100）， 其余场景的成功率目前全部是 0，等着被测出来或被证伪。

另外两条纪律，贯穿全文：

  • 不把已有能力改名叫新成果。"说一句话走到点""脚上有轮子滑行""单次踢球" 这些 DuckKing 已经会（stage.py 的 A* 寻路、官方轮滑、官方踢球策略）， 本文不会把它们当成新场景重新包装。新场景必须是过去没有的条件控制、连续物体控制或新接触环境里的身体协调。
  • 官方步态永远冻结。所有方案都是在官方 velstand.onnx 之上加一层新策略， 不改写官方 ONNX、不重训官方权重、不用"隐藏的外力"把鸭子扶正。

3. 10 个场景共用的技术骨架

10 个场景看着不一样，底下是同一套结构。这套结构已经在转盘平衡上跑通过一遍， 所以它不是空想——是已验证的范式，只是换任务。

3.1 动作空间：其实已经很干净了

DuckKing 对外暴露的动作接口是 13 维命令向量，官方步态把它翻译成 14 维关节位置目标：

command[0:3]　= (vx, vy, vyaw)　　　// 前后 / 横移 / 偏航
command[4:7]　= (pitch, yaw, roll)　// 颈部与头部
command[9:12] = (z, roll, pitch)　　// 身体姿态（高度与倾角）
// 训练频率 10 Hz ｜ 官方步态 50 Hz ｜ MuJoCo 物理 200 Hz

这意味着 RL 的动作空间天然就是"该往哪走、该转多少、该把身子歪多少"， 而不是 14 个关节的连续角度——后者需要重新训练低层策略，工作量和风险都高一个量级。 大多数场景直接复用这一层即可；只有 #6 上台阶需要动到关节级（残差或独立低层策略）。

3.2 观测：先老老实实用仿真真值

平衡场景的 25 维观测已经被验证够用（目标方向 2 + 朝向 sin/cos 2 + 投影重力 3 + 机身速度 6 + 盘倾角 2 + 盘角速度 3 + 支撑/高度 2 + 上次动作 3 + 时间比例与停盘标志 2）。 其他场景照抄这个套路，把"盘倾角"换成"目标相对位置"这类任务相关量即可。

必须写进每一页界面的声明：这些观测全部来自仿真引擎的真值， 不是摄像头画面。仿真里这么叫"状态"，实机上就得靠传感器或状态估计器替代， 并重新验收。不要让观众以为这只鸭"看得见"。

3.3 奖励：拼装式，方便做对照实验

平衡场景的 8 项奖励是拼起来的（直立 1.0 / 中心 2.0 / 朝向 1.0 / 向心进展 8.0 / 滑移 −0.15 / 平滑 −0.025 / 摔倒 −10 / 成功 +20）。这套拼装方式带来一个很有用的副产品： 换掉其中一项就变成一次对照实验。#4 稀疏奖励对照、#7 安全与速度的取舍， 用的都是这个性质。

1四算法赛马 · 四只鸭同场竞速（但结论不是"谁更快"）

观众看懂度★★★★★
教学点策略型 vs 值型 · on-policy vs off-policy
结论没有全局最优算法
工作量中高（4 份训练 × 4 种条件 + 1 个矩阵页）
依赖需要一个"走到彩门"的简单任务环境

观众看到什么

四只颜色不同的鸭站在四条赛道起点，一声令下同时出发冲同一个终点。最先到的那只赢。 没有一句解释观众就已经知道在比什么。

但赛马只是入口，不是结论。观众很自然会把"谁先到"读成"谁更强"， 而这恰好是错的——所以紧接着必须给出那张矩阵和记分板： 换一行条件、换一个指标，赢家就可能换人；每个算法都会在某一项上第一，但没有一个全项第一。

官方为什么做不到

官方那 10 个策略各自独立、每次只干一件事，压根没有"多个策略同场比较"这个概念。 DuckKing 现在也只有一只鸭跑一个策略（多鸭场景里的第二只由编排控制）。

RL 到底在学什么

四份策略学的是同一个任务：从起点走到彩门并停住。 PPO / A2C / REINFORCE 走策略型路线（直接输出动作概率）， DQN 走值型路线（先估每个动作值不值得，再选）；A2C / PPO / REINFORCE 是 on-policy （数据用一次就扔），DQN 是 off-policy（同一批数据能反复学）。

诚实的风险

服务端同时最多跑 4 个 MuJoCo 世界，四只鸭正好顶格，再加别的就超限； 更稳的做法是预先训练好、现场回放——那台上就必须明确说"这是回放，不是实时"。 工作量也从"中"升到了"中高"：4 个算法 × 4 种条件 = 16 组训练， 其中任何一个超时的算法都会让矩阵缺格（缺格必须照实标"未完成"，不能拿别的条件的结果填）。

这一节专门防一个具体的翻车：把演示讲成"PPO 更强"。
  1. 单条件必然导出单排名。只跑一种任务条件，排名就是固定的，观众一定会读成算法强弱。 所以条件必须事先定好并公示：直线冲刺 / 目标随机 / 有障碍绕行 / 步数预算受限，四种都要跑。
  2. 单指标必然导出单排名。"谁先到"只是五个指标之一。 再补三个便宜的：达成阈值所需的训练样本数、推理一次的耗时、终点偏移 20% 后还能不能到。
  3. 不能看完结果再挑条件。条件与种子必须事前固定并公示； 看到结果之后才挑"PPO 在这行赢"的那一行去演，等于伪造结论——这是红线。
  4. 不能把不同算法跑在不同任务上再比。那是本演示最容易犯、也最不容易被观众发现的错。
  5. 如果实测下来 PPO 每次都赢，就如实说。然后补一句"这说明这个任务适合 PPO，不代表 PPO 更好"， 并当场出示它在样本效率或推理开销上落后的那一格。诚实版本比好看版本更经得起追问。
还缺一条赛道：不加它，这个场景很可能一测就作废。 第 10 节的基线审计给出一个要命的结论：赛马的任务是"走到彩门"， 而这恰恰是仓库里已经实现的能力——stage.py 的 A* 加官方步态就能完成。 按本文的验收口径"基线已能完成 ⇒ 场景作废或升级难度"，#1 会被自己的基线否掉。 修法不是偷偷换任务，而是把"官方步态 + A*"加成第五条赛道：
赛道它是谁它代表什么
PPO / REINFORCE / A2C / DQN我们自己学的策略层 "能不能学出一个不用导航的策略"
官方步态 + A*
必须加		 不学任何东西 "直接用现成策略 + 几何导航够不够"

加了这一条之后，赛马真正回答的问题就不再是"哪个算法更强"， 而是"你要不要自己学一个策略，还是直接用现成策略加导航"—— 这才是 DuckKing 真正要回答的工程问题，也是我们冻结官方步态这个决定的正反面。 而且这条赛道天然又拆掉了一层"算法排名"的叙事。

诚实边界也要跟着改：如果第五条赛道赢了，那结论就是 "这个任务上不必学策略，现成的官方步态 + A* 就够"—— 这同样是一个诚实且有价值的结论，不能为了保住 RL 的叙事而把这条赛道藏起来。

课堂上要讲的一句话："没有哪个算法在所有指标上都第一。 选算法之前先回答一件事：你更在意跑得快、练得省，还是部署省？"

2带球闯彩门 · 从踢一脚到全程控球

观众看懂度★★★★★
教学点闭环控制 vs 一次性开环
工作量中
依赖需要新的球与彩门几何

观众看到什么

一只鸭守着一个球和一个彩色门框。球进了 → 成功；球偏了 → 鸭自己绕回去修正，再顶。 观众会自发地喊"再来一次"，因为失败与成功的差别非常具体（球在门里还是在门外）。

官方为什么做不到

官方 ball_kick_left/right.onnx 是一次性（episodic）策略： 站在球前触发一次 0.5 秒的踢球动作，踢完就结束。 它不会看球在哪、不会等球滚到位、不会在球偏了之后再来一次。

RL 到底在学什么

观测：球相对位置与速度、自身位姿与速度、离目标还有多远、上一步动作。 动作：13 维命令向量里的速度部分。 奖励：向心进展（连续）+ 球离门更近（连续）+ 触球时机（事件）+ 进球（稀疏大额）+ 出界与超时惩罚。

诚实的风险

官方步态是冻结的，能不能稳定触球本身就是个未知数；必须先做可行性实验， 不能一上来就加大训练预算硬训。另外不允许在开场偷偷把球摆到好踢的位置—— 那等于把难点藏起来，失败率会失真。

课堂上要讲的一句话："官方那一下是开环的——按一下就不管了； RL 学的是闭环：看一眼现在的球在哪，再决定这一秒怎么走。"

3让行鸭 · 两只鸭相遇，谁先侧身

观众看懂度★★★★★
教学点多智能体 RL · 僵局与信用分配
工作量中低（最适合较早交付）
依赖duo 多鸭世界已存在

观众看到什么

两只鸭从走廊两头对向走来，撞上之前必须有一只侧身让开。戏剧性很强： "谁让谁"每次都不一样，观众会争论。更妙的是可以加一个观众投票环节—— 观众猜这次谁会让。

官方为什么做不到

官方策略没有"同伴"这个概念，它只知道自己的关节和重力。 现在工坊里的"相向碰面"是固定速度的编排（速度写死、时长写死）， 双方根本不做决策，也就没有"让"这回事。

RL 到底在学什么

每只鸭各自观测：对方相对位置与朝向、最近接触距离、自己的速度与朝向、剩余时间。 动作：速度命令。奖励：接近目标、保持安全间距、双方都让开（避免僵局）。 这是典型的多智能体问题：每只鸭只看自己那份奖励， 就会出现"两边都等对方先动"互相卡死的僵局。

诚实的风险

必须先量出强基线——现有的 A* 寻路加跟随/停走规则。 如果脚本就能完美让行，那这个场景就没有 RL 的增量，应当诚实放弃。 多智能体训练还容易不稳定，可能需要参数共享（两只鸭共用一套权重、按身份区分观测）。

课堂上要讲的一句话："多智能体最难的不是让每只鸭走好， 是让它们不互相等——两只鸭各自都觉得自己该先动，结果谁也不动。"

4错误的提示 vs 没有提示 · 第 1 局指对了，第 2 局指错了

观众看懂度★★★★★
教学点奖励塑形 · 局部最优 · 探索 vs 利用
工作量中（与 #2 共用环境）
依赖#2 的任务环境 + 一个可切换的提示信号

观众看到什么

第 1 局：场地里只有一个目标，提示指的就是它。两只鸭同时出发， 有提示的那只一路直奔、很快得分；没提示的那只在场上转来转去、很久才碰到。 观众的直觉在这里被强化——"给点提示当然有用"。

第 2 局：场地中央多放了一个更近、更亮、写着"奖"的假目标， 而真目标挪到了不起眼的角落。策略没变、提示规则也没变（"朝最近的目标走"）， 但提示现在指向了假目标。于是：有提示的鸭一头扎进假目标、拿到小分就卡在那里； 没提示的鸭继续乱撞，居然覆盖到了角落里的真目标，拿到满分。

结果反转。观众的疑问是现成的："明明给提示的那只更差？"

官方为什么做不到

官方策略是单一确定的行为，它既不会"迷路"，也不会"被一条错的方向带偏"—— 因为它根本没有搜索过程，也没有"提示"这个输入。 只有当决策来自策略分布、且环境里有可被利用的局部奖励时，这两个问题才会同时出现。

RL 到底在学什么

这里被拆成两件独立的事，必须分开讲，否则观众只会记住"没提示的那只更好"：

其一：塑形信号本身。策略学的是"朝着提示指的方向走"。 提示在第 1 局指对了真目标，在第 2 局指错了假目标——同一套权重，两种表现， 差别全部来自输入信号指向了哪里。这叫奖励塑形指向了局部最优。

其二：没有提示时的行为。没有 progress 信号，策略只能靠自身随机性做覆盖式搜索。 所以"满场乱撞"不是设计目标，而是信息不足时的默认产物； 真正的解法是带随机性的探索机制（ε-greedy / 熵正则）加上被修正过的塑形信号。

并行的补充实验（不上台，但要在报告里写）： 真正严格的对照是"progress 分量开 / 关"——同网络、同超参、同种子分布、同评测集，只改这一个变量。 它会顺带暴露一个诚实的可能：稀疏奖励下可能根本训不出来。 如果结论是"训不出来"，那也是一个合法且有价值的结果（说明奖励设计是整个实验的承重墙）， 照实写，不要为了上台好看而悄悄换回有提示的版本。

诚实的风险

第 2 局的反转不能靠"看起来像"蒙混：假目标必须由程序明确定义（更近 + 更高亮 + 单独计一份小分），并且观众要知道真目标在哪、鸭不知道。真目标位置不能临时挪， 否则观众会觉得是耍赖。

还有一个诚实的可能：没提示的那只也可能撞进假目标然后赖在那儿， 两局都卡住、谁也没赢。那也是一个合法结果，照实播报即可， 不能偷偷换回第 1 局的配置重演一遍。

怎么向观众说明"满场乱撞在某些场景下反而更适用"——三句话，按顺序说：
  1. 先承认直觉是对的一半。"没提示那只确实更慢——在第 1 局里， 有提示是严格更好的，观众没看错。"不把观众的直觉说成蠢，教学才立得住。
  2. 再给出条件。"但它更好，只是因为那条提示当时是对的。 一旦提示可能指错，服从提示的下限就变成了'直奔陷阱'， 而覆盖式随机搜索的下限只是'慢'。慢，和掉进陷阱，是两种不同的失败。"
  3. 最后划清边界。"所以正确的说法不是'乱撞更好'，而是： 在提示不可靠时，无偏探索的期望收益高于服从一条可能错的提示； 而一旦提示被修正，就应该让位给利用。 工程上真正要做的是把塑形信号修对，再留一点随机性兜底， 而不是刻意让鸭子乱撞。"
这一条为什么排在演示清单里这么靠前：它讲的其实就是我们自己的产品。 DuckKing 的语音提示就是那条塑形信号——观众一句话说"往左走"，就是给鸭的一个 shaping。 提示指对了是加速；场上一旦多出一个更近的目标，"朝最近的目标走"就会把鸭带偏。 这个演示不是在讲一个 RL 概念，是在讲我们的交互设计该怎么防错。
课堂上要讲的一句话："一个错的提示，比没有提示更糟。 奖励不是打分标准，它同时是信息——信息给错了方向，比不给信息更危险。"

5守门员 · 提前站到落点，而不是扑过去

观众看懂度★★★★☆
教学点预测与模型预测控制
工作量中
依赖ball 场景与球的接触判定可复用

观众看到什么

球被踢出去，鸭子没有扑过去追，而是提前挪到球的落点，等球来。 这个反直觉的行为本身就是最好的教学素材：观众会以为它该去追球， 然后发现它根本不去。球进了 → 成功；球进了但鸭没挡住 → 失败，判定清晰。

官方为什么做不到

官方没有防守这个概念，也没有"球的未来位置"这种预测。 更关键的是：官方踢球策略是让球离开的，防守需要的是完全不同的目标函数。

RL 到底在学什么

观测：球的位置与速度、自己的位姿、球门几何。 动作：速度命令。奖励：球被挡在门线外（事件）+ 拦截时刻的落点误差（连续）+ 恢复站立（连续）。 如果球速可控，这一关就能自然地引出模型预测：先算一步落点，再决定站位。

诚实的风险

碰到球不等于守住门——必须有门线判定与接触时刻的完整记录。 否则策略会学出"用身体把球顶开再撞出界外"的投机解。 另外球的速度若不受控，拦截窗口会宽到失去教学意义，需要把发球档位也纳入任务定义。

课堂上要讲的一句话："反应式的做法是看见球就动；预测式的做法是先算出球会去哪， 然后去那个地方等。多算的那一步，换来的是少跑一半的路。"

6上台阶 · 官方步态没学过的动作

观众看懂度★★★★★
教学点残差 RL 与低层关节策略
工作量高
依赖需要新地形，且可能需要绕过官方 ONNX

观众看到什么

一只鸭走到台阶前，抬腿、踩上去、站稳。观众会有本能的紧张感 （"它会不会摔"），这正是最好的现场效果。

官方为什么做不到

官方步态在平地上训练，官方文档明确写了身体下沉能力"没学会"， 慢速原地旋转也偏弱。跨台阶需要精确落脚与重心转移， 这不在官方策略的能力范围内，也不能靠把速度调快蒙混过去。

RL 到底在学什么

这是唯一一个需要动到关节层的场景。两条路线：
① 残差 RL：保留官方步态做基策略，RL 只输出一个有界的关节修正 q_ref = q_base + clip(Δq, −δ, δ)；
② 独立低层策略：绕过官方 ONNX，直接训 14 关节策略。
先做①，失败再做②——因为①便宜得多。

诚实的风险

工作量最高的一个。禁止用隐藏的地面补支撑把鸭子扶上去， 那是最容易被评审抓住的作弊点。新地形意味着要重新评估官方步态在该接触条件下的有效性。 训练吞吐未知（本机 CPU 单线程），不能拿转盘场景的半小时去外推这里要跑多久。

课堂上要讲的一句话："残差 RL 的思路是：不推翻原来的能力，只在它不够用的时候补一刀。 先用小补丁试，不行再考虑自己重学走路。"

7轮滑转向 · 用身体倾斜换方向

观众看懂度★★★★☆
教学点欠驱动系统 · 姿态与代价
工作量中
依赖rollers 场景已有

观众看到什么

脚上装四个被动轮的小鸭在地面上滑行。它想拐弯时不是靠腿蹬，而是把身子往里一歪， 滑行方向就跟着变。这个因果关系观众能直接看懂，而且和"拐弯要打方向盘"的日常经验正好相反。

官方为什么做不到

官方 roller.onnx 只有被动轮上的滑行，没有转向控制。 现有 DuckKing 的轮滑场景也只有"滑行"和"下蹲"两个一次性技能，方向始终是脚本给的。

RL 到底在学什么

观测：身体姿态与角速度、滑行速度、目标方向与朝向误差。 动作：身体姿态（roll/pitch）+ 少量速度修正。 奖励：朝目标方向的实际位移（不是命令速度）+ 姿态稳定性代价 + 滑移代价。 这关教的是欠驱动：可用的执行器比要控制的自由度少，只能间接地换方向。

诚实的风险

被动轮与地面的接触模型直接影响结论， 而官方训练用的是电压/负载摩擦模型，本仓库是 XML 位置伺服—— 动力学不一致，这个场景尤其敏感。 另外必须先量官方基线：如果官方步态本来就能转，这场景直接作废。

课堂上要讲的一句话："欠驱动就是你手上只有两个旋钮，却要管住三个东西。 这时候策略得自己学会用'歪身子'去换'转弯'，因为那是你仅有的杠杆。"

8推箱入库 · 先决定推哪一格，再绕过去

观众看懂度★★★★☆
教学点层次 RL · 长时程信用分配
工作量中
依赖需要新物体与接触判定

观众看到什么

一只鸭和一个箱子，格子标着目标。鸭子先绕到箱子后面，再顶。 观众能看出层次感：它不是每一步都在想箱子，而是隔一会儿才做一次"下一步往哪格推"的决定， 中间那段走过去只是执行。

官方为什么做不到

官方没有手臂，不能抓也不能推；官方也没有"物体"这个概念。 DuckKing 现在最接近的是嘴部搬运一根固定轻棒，那是夹取，不是推， 接触方式和判据都不同。

RL 到底在学什么

这是"层次 RL"最好讲的例子：
高层（0.5 Hz）：选下一个目标格，输出"往哪推"；
低层（10 Hz）：连续走位去贴住正确的推点。 它同时也是"长时程信用分配"的例子——推这一下有没有用，要到很多步之后才看得出来。

诚实的风险

没有手臂意味着推点受形体限制，需要防止"撞飞箱子"这种取巧解法 （接触力上限要算进判据）。另外要防策略学会"把箱子撞出场地"， 所以必须定义清楚"入库"的判定（位置 + 朝向 + 未越界）。

课堂上要讲的一句话："RL 最怕的是'做了很多步才见效'。 层次化的思路是：把大决策和细动作拆开，每一步只管一件自己看得见后果的事。"

9三鸭三舞 · 同算法、三个种子、三种舞

观众看懂度★★★★☆
教学点熵与多样性 · 随机性的价值
工作量中低
依赖可复用现有动作编排与四鸭场景

观众看到什么

三只鸭各跳各的：步频不同、摆幅不同、停顿位置不同。 观众第一反应是"这三个是分别编的"——然后被告知其实是同一个算法，只是初始化随机数不同。 这个反直觉的瞬间，正好把"随机种子"这件平时很无聊的事讲活。

官方为什么做不到

官方 10 个策略里没有任何舞蹈策略。 DuckKing 现在的两个舞步（闪身步、狗熊哆嗦毛）是我们自己写的确定性编排—— 可复现，但不"自己找"。

RL 到底在学什么

奖励可以只是"别摔倒、保持节奏、能量别太大"，风格是涌现出来的。 熵系数控制随机性：太低会收敛成一个僵硬的套路，太高会乱晃。 这里也能顺带讲"条件化策略"：把风格 ID 拼进观测，一个网络就能演出多种风格。

诚实的风险

最难的是量化：不能用"看着不一样"当结论。 需要能算的差异指标（例如重心轨迹的相位差、步频分布、重心高度方差）， 否则这一关会被质疑"这只是随机噪声"。 另外要确保三只鸭的差异来自策略，而不是来自初始姿态不同。

课堂上要讲的一句话："随机种子不是噪声，是可能性。 同一个算法换个种子，能长出不同的风格——这正是在提醒我们：探索本身有价值。"

10观众投喂目标 · 鸭子当场改道

观众看懂度★★★★☆
教学点上下文 bandit · 只做选择，不做学习
工作量低
依赖复用现有任务仲裁与房间状态

观众看到什么

观众在页面上点一个位置（或用一句话指定一个方向），鸭子当场改道过去。 参与感最强的一个场景——观众从"看别人表演"变成"给角色下达指令"。

官方为什么做不到

官方遥控 App 只能发预设动作（走、跳那几个），没有"被观众实时指定一个目标"这种闭环。 DuckKing 现在的任务编排也没有把观众输入接进决策环路。

RL 到底在学什么

这一关其实不需要训练：每换一个目标就重新做一次选择， 用上下文 bandit 就够——只有"选择 → 得到奖励 → 更新"这一层，没有状态转移。 它正好用来对照："什么时候需要完整的 MDP，什么时候 bandit 就够？"

诚实的风险

最需要小心的是不要把选择器说成训练。 现场可以说"它选了更近的那个目标"，不能说"它正在学习"—— 除非真的在线更新了权重并记录了对照数据。 这一关是"寓教于乐"里最容易越界的一条。

课堂上要讲的一句话："有时候你不需要学一整套，只是每次重新选一次。 bandit 就是这么回事——省下来的时间，往往比多训几轮还值钱。"

7. 90 秒上台脚本

10 个场景不可能全上。下面是一份只挑了 5 个的 90 秒版本， 每 15–20 秒换一个看点，节奏由"好看"递进到"有概念"：

时间场景观众看到只讲一句话
0–15 秒#1 四算法赛马四只鸭同时出发冲终点，接着亮出那张空矩阵 "同样的物理、同样的任务，四个脑子——但没有哪个脑子在所有条件下都第一。"
15–32 秒#3 让行鸭两只鸭相遇，其中一只侧身让开 "它们各自看着对方做决定——两只鸭怎么才能不互相等？"
32–50 秒#4 提示对照第 1 局提示指对了，第 2 局指错了 "错的提示，比没有提示更糟。"
50–70 秒#5 守门员球飞来，鸭子提前站到落点 "它没有去追球，它算了球会落在哪。"
70–90 秒#10 观众投喂观众一指，鸭子改道 "现在，轮到你给它下指令了。"
现场纪律：观众在台下，讲解必须先演后说。 先让画面动起来，再补那一句概念。反过来做（先讲三分钟 RL 原理）会立刻失去注意力。 每段结束都要落一句"这是 RL 学的，不是官方本来就有的"，把诚实边界说在前面， 而不是等人来质疑。

8. 诚实的边界：现在一个数字都还没有

事项现在的真实状态不能怎么说
本清单 10 个场景的成功率全部为 0 尚未训练或评测 不能说"能做到""已验证""准确率 X%"
物理载体纯仿真 MuJoCo 3.3.7 CPU，无实体机器人 不能说"实机学会了""真机通过"

训练耗时未知 本机 CPU 单线程，不能外推 不能承诺"半小时训完"
官方步态冻结 一个参数都不改 不能暗示"我们重训了官方步态"
与既有能力的关系不重复 走路/到点导航/轮滑/单次踢球均为已有 不能把这些改名叫新成果
算法对照的结论范围条件相关 单条赛道上的第一名只代表"这个任务条件下更快" 不能说"PPO 比 DQN 强"，只能说"在这个条件下 PPO 先到"
与官方基线的关系待测 每个场景都要有同种子的官方基线；基线已能完成 ⇒ 场景作废或升级难度 不能跳过基线直接报 RL 的成功率，也不能把基线跑出来的最好那一次算成自己的成绩
基线的限速问题已知软肋 几何基线自己把前进命令压在 0.15–0.34，RL 可用全幅 [-1, 1] 不能只拿被限速的导航器当基线就宣布获胜，必须补一条不限速的强基线

9. 落地顺序与 go / no-go 门槛

推荐顺序同时也是实现顺序的大部分——只有 #1 与 #2 需要调换： 赛马（#1）需要"走到彩门"这个最简任务环境，它是 #2 带球环境的子集， 所以工程上两者可以并行开工。

#1 的工作量要按矩阵算，不是按一条赛道算：4 个算法 × 4 种条件 = 16 组训练。 建议先只跑通"直线冲刺"这一行的 4 组，把回放页和记分板做出来， 再逐行补齐；任何一行没跑完就在矩阵里照实标"待测"， 不要用已经跑完的那一行去填别行。

阶段做什么go / no-go 门槛
0 契约与接入 用已跑通的转盘 PPO 做一次小规模接入检查：统一模型/观测/动作契约、工件格式、房间与取消链路 兼容性、取消、重复与乱序、协议 framing、reset、房间隔离用例全过； 契约不过就不接新场景

2 算法对照 在 #1 的底座上分别跑 PPO / A2C / REINFORCE / DQN 每个算法 ≥3 个训练种子、每个种子 ≥100 个封存回合； 报告 95% CI；无增益则不得宣称 PPO 优势

公平比较的统一要求：相同种子、相同初态、相同扰动组合、相同动作约束， 对比对象固定为「固定姿态 + 官方策略 + 几何规则基线（如 A*）」。 训练 / 验证 / 测试按扰动组合分开，选定模型后才看最终测试； 不拿反复调过的 seed 充当泛化能力。

附录. 三个备选：让动作真的落到场景上

下面三个是针对"转盘场景里，鸭子的反馈只自适应自己、影响不到场景" 这个问题提出的备选。它们尚未纳入上面的推荐顺序——要先定下做哪几个、 以及要不要替换现有条目。成功率同样全部为 0。

先把转盘场景的问题钉在代码上

这个批评是准确的，而且可以逐条对到实现上（src/duckking/balance.py）：

观察代码事实含义
转盘是开环的 _drive_disc() 用 desired = f(t, level, difficulty) 算出目标倾角与转速， 限速后写进 data.ctrl[disc_act]；公式里没有鸭子的任何状态 鸭子的动作没有任何路径能改到转盘上。策略能"读"它，改不了它
动作空间只有 3 维 step() 校验 action.shape != (3,)，且 gains = np.maximum(action, 0) 配一条显式的居中／朝向反馈律 这个场景里 RL 学到的是反馈增益的大小，连完整行为都由工程先验给定
奖励全是自身状态 REWARD 八项：upright / center / heading / progress / slip / smooth / fall / success 没有一项是"我对场景做了什么"。整个任务在奖励层面就与"改变世界"无关
场景与策略是松耦合的 转盘停下来之后，策略学到的全部内容立刻失去意义 它是一个抗扰控制器，不是"在物理世界里做事"

所以更准确的说法不是"转盘场景做得不好"，而是： 它是本清单里唯一一个只有抗扰、没有作用力的场景。 下面三个备选分别换掉它——它们改变的东西各不相同。

备选 A · 顶球开闸 · 改变场景的开关状态

观众看懂度★★★★★
教学点工具使用 · 长时程信用分配 · 不可逆动作
工作量中高
依赖球场景 + 新几何（闸门、撞针）

观众看到什么

场地一侧有一道闸门，门后是目标区。场地中央立着一个撞针开关， 鸭够不着。鸭只能用身体把球顶过去——球撞上撞针，开关被压下， 闸门永久升起，同时球被弹开滚走。

观众看懂的是一句大白话："它用球把门顶开了。"

闭环在哪

鸭 → 顶球 → 球撞针 → 闸门状态改变 → 场地几何变了 → 鸭的观测与可行路径跟着变 → 鸭重新决策。动作真的落在了场景上。

RL 到底在学什么

  • 工具使用：球不是要被送进目标的东西，是要被用的工具。
  • 长时程信用分配：奖励在"撞针被触发"那一刻给，但"从哪个方向、离多远去接近球" 是很久之前的决策——这正是 credit assignment 的经典难题。
  • 不可逆动作的代价：撞针撞下即锁定，选错方向就没有第二次。
  • 结果导向而非动作导向：撞针有角度容差，擦边只会把球打飞； 而且撞完球滚到哪里由物理决定，鸭可能把自己堵死。

诚实的风险

撞针的"角度容差"和"一次性锁定"是我们自己设计的新几何规则，不是官方能力，必须说清楚。 球撞完的落点由 MuJoCo 决定，不能预设；若每次都落在同一位置，那是调参调出来的，要如实说明。 也完全可能出现"顶太狠球飞出场外导致本轮无法完成"——那是真实失败，必须能如实播报， 绝不能先用脚本把球摆到好顶的位置再交给策略。

课堂上要讲的一句话："它不是在踢球，是在用球开锁—— 但门开了不代表人能过去，球还滚到哪儿去了它也不知道。"

备选 B · 推倒骨牌造台阶 · 改变场景的几何地形

观众看懂度★★★★★
教学点环境改造 · 链式因果 · 不可逆规划
工作量高（三者里工程风险最大）
依赖新资产（骨牌）+ 稳定的多米诺参数

观众看到什么

场地中央立着一排小骨牌。鸭子一头撞在第一块上，骨牌哗啦啦倒下来， 倒下的骨牌正好在它面前形成一段矮台阶，它顺着爬上去，够到高台上的目标。

如果撞歪了，骨牌倒成一堆乱石——台阶变成了障碍，路反而更堵。

闭环在哪

鸭 → 撞第一块 → 骨牌倒下 → 地形永久改变 → 可通行性变了 → 观测变了 → 重新规划。 它不是在一个固定场景里走路，它是先把场景改造成另一个场景。

RL 到底在学什么

  • 环境改造：动作改变的是地形本身，不是鸭自己在地形上的位置。
  • 链式因果：撞第一块可能引发连锁，多米诺效应让"一个动作"变成"一串后果"。
  • 结果导向：同样的撞击动作，倒向目标就是台阶、倒歪就是障碍—— 策略必须对后果负责，而不是对"我撞了一下"负责。
  • 不可逆规划：撞之前必须想清楚，撞完不能重来。

诚实的风险

骨牌是新增资产（官方没有），必须说清楚。而且 MuJoCo 里的刚体"整齐倒成一排" 相当难调——这是三者里最容易做砸的一个。

最要紧的一条纪律：倒下后形成可攀爬台阶，必须是 MuJoCo 刚体模拟的结果， 不能先用动画把骨牌摆倒再让鸭子走上去。那是伪造演示，没有意义。

另外"倒下后恰好搭成坡"很可能靠反复调骨牌尺寸与间距才成立， 要如实说明这是调参结果，换个物理版本可能就不成立。

顺带一个工程价值：这条其实是 #6 上台阶的前置。 官方步态没学过非平地，而骨牌倒出来的那段矮坡，恰好能给 #6 提供一块"非平地"—— 先让场景自己长出地形，再让策略学怎么上去。
课堂上要讲的一句话："它没有学会走台阶——它先把台阶造出来了。 在物理世界里，'解决问题'有时候等于'改造问题'。"

依赖duo 多鸭世界（已存在）+ 官方步态当"会动的对象"

观众看到什么

两只鸭。A 负责一件事：把 B 送到目标点。但 A 没有手臂、抱不动 B， 唯一能改变 B 的方式是撞；而 B 走的是它自己的官方策略，一直在场上移动， 不是等着被撞的靶子。

观众看到的是：一只鸭在后面追着撞，另一只鸭被撞得滑出去。 要让 B 停在目标点上，A 得预判 B 会往哪躲、撞多重才刚好。

闭环在哪

A 撞 → B 的位置与速度改变 → B 的行为也随之改变 → A 观测到的场景变了 → A 重新瞄准。

RL 到底在学什么

  • 间接施力：A 不能"move B"，只能改变 B 的动量。这与遥控指令是两种完全不同的能力。
  • 施力控制：撞击力度 → 停点距离，力度是策略要连续决策的量。
  • 意图预判：B 是会动的物体，策略必须预测它的下一步。
  • 多智能体：B 用官方 velstand.onnx 走自己既有的路线， 所以这是"我们的策略 对上 官方策略"，而不是两个训练出来的智能体。

诚实的风险

B 的运动必须来自官方策略本身，不能写成脚本——脚本让 B 躲开，就等于假装有了多智能体。 这意味着 B 的行为会随官方策略版本变化，跨版本不可比。

两鸭同场要占掉 2 个 MuJoCo 世界（上限 4 个），还留得下，但不能再叠加别的场景。

另外要留意观感：观众可能把"推同伴"看成欺负——演示要包装成搬运／比赛任务， 而不是攻击。

课堂上要讲的一句话："它没办法直接指挥同伴——它只能推。 而被推的那只，还在按自己的规则走。"

三个备选怎么挑

备选改变的是什么最好讲的一点工程风险观众看懂度
A 顶球开闸场景的开关状态（门开了） 工具使用 + 信用分配：它是用球开锁，不是在踢球中高★★★★★
B 推倒骨牌场景的几何地形（台阶长出来了） 环境改造：不是学会走台阶，是先把台阶造出来高★★★★★
C 推鸭过门另一个智能体的状态（轨迹变了） 间接施力：改不了目标，只能改轨迹中★★★★☆

如果只做一个：选 A。它是三者里唯一既有强舞台效果、工程风险又可控的； 球场景已经存在，闸门与撞针只是新几何。

如果做两个：A + B。两者改的是完全不同的东西（状态 vs 几何）， 而且 B 顺带给 #6 提供非平地地形。

C 可以留到后面。它最便宜，但需要 duo 场景稳定、B 的官方策略版本可比， 教学点也比 A/B 弱一档。

三个备选共同的诚实红线（照抄第 10 节与第 8 节的纪律）：
  1. 新资产（闸门、撞针、骨牌）都是我们自己加的，不是官方能力，台上必须说清。
  2. 场景的改变必须是 MuJoCo 物理算出来的结果，不许用脚本或动画摆好再交给策略。
  3. 失败（球飞出场外、骨牌倒成障碍、B 撞不到）必须能如实播报，不能重播成功的那次。
  4. 三个备选的成功率同样目前全部为 0；没跑之前不能写任何数字。
