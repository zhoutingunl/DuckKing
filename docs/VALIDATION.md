- Microduck RL：`b02fdea4902c2b93b7d34a83a6f05da4ececb7d3`。

已完成本机依赖安装、Rust 编译、官方 ONNX 策略下载与 headless 启动。启动时官方检查报告控制循环 50 Hz、无漏帧，身体高度约 0.116 m，姿态竖直。

DuckKing 适配器已向该真实仿真进程发送点头、前进、停止，接收真实状态。实测发现 0.12–0.2 m/s 的短指令位移很小；改用 0.35 m/s 后，1.2 秒动作的一次实测位移约 0.14 m，姿态保持稳定。该数值是一次观测，不是闭环距离保证。

初次脚本执行结束后，运行器会清理后台进程，因此新增 `run_simulator.sh` 保持父进程存活，并在退出时关闭仿真。测试也发现需要保留点头开始时的头部姿态，不能把模型参考关节值无条件当作指令零位。

最终演示的逐次动作和物理状态见 [official-simulation.json](media/official-simulation.json)。

该 15 秒录制中，前进任务在收到停止后被标记为 `cancelled`，最终速度指令接近零、未跌倒；控制循环约 50 Hz，最终遥测累计报告 1 次漏帧，不作为严格实时保证。

## 真实灵矽联调

已使用用户提供的本地平台 API Key 创建专用 DuckKing 智能体，配置工具调用，并通过设备激活码完成绑定。Key 和设备 token 未写入仓库。

实际验证：

1. 将系统合成语音“请你点点头”上传真实灵矽服务，收到正确 STT，云端执行 `initialize`、`tools/list`、`tools/call`，本地点头完成，返回真实 TTS 音频。
2. 使用官方 robotd/MuJoCo 后端上传“请你向前走一点”，云端调用前进工具，任务完成并返回真实语音确认。
3. 在浏览器中使用合成语音作为麦克风输入，验证 AudioWorklet → 后端 → 真实灵矽 → 工具调用 → 页面动作与 Web Audio 播放；录制了视频和实际回复音频。
4. 新增两个节目后，真实灵矽分别识别“来一段闪身步”和“来一段狗熊哆嗦毛”，调用对应工具并在完成后语音确认。录制程序按本次请求的动作 ID 验证结果，排除旧日志误判；证据见 [闪身步](media/live-flash-step.json) 和 [狗熊哆嗦毛](media/live-bear-shake.json)。

参考 [点头联调记录](media/linx-nod-verification.json)、[官方仿真语音联调记录](media/linx-physics-verification.json)、[浏览器真实语音记录](media/live-linx-voice.json)。这些是真实服务结果，与单元测试中的假服务分开保存。

实测暴露并修复的问题：OTA 当前返回 `ws://` 官方地址，客户端应升级到该主机文档支持的 `wss://` 后连接；既不关闭 TLS 校验，也不把平台 API Key 当作设备 token。

## 本地物理实验室验收（2026-10-24）

本机 macOS / Python 3.12.12，MuJoCo 3.3.7、ONNX Runtime 1.19.2，在 CPU 上运行固定官方模型和策略，未使用 robotd。`scripts/verify_scenarios.py` 实际执行单鸭左脚、右脚踢球，以及共享世界内的双鸭发现、相向碰撞和合唱控制；记录见 [physics-scenes.json](media/physics-scenes.json)。脚球接触检查命中对应 `ankle_left/right`，球位移来自 MuJoCo 自由关节；双鸭接触按不同机器人所属 geom 检查，未施加伪造位移或预设碰撞计数。

真实灵矽联调使用 macOS Tingting 合成中文录音，经 `/scene-voice` 发送 PCM，经过真实 STT / MCP / TTS。左、右脚分别识别正确并调用对应动作，均确认脚球接触；本次测得位移约 1.46 m / 1.17 m，下行音频分别 207 / 124 帧。证据 [scene-voice-verification.json](media/scene-voice-verification.json) 不包含账号、token 或设备标识。它验证后端到云端的链路，不冒充真人麦克风或人工听音测试。

浏览器测试使用真实本地物理后端，覆盖左右脚按钮、球位移、双鸭接触、发现同伴、启用合唱音频、停止与手机布局，以及依赖失败时明确报错。单元测试额外覆盖错场景、缺少左右脚参数、重复请求、切场景取消、双鸭停止、物理推进异常与重置，以及踢空时不返回成功。合唱浏览器检查验证音频排程；未测量扬声器输出的样本级同步误差。

本地检查：161 项 pytest 通过；行覆盖率 98.89%、分支覆盖率 96.58%；Ruff、前端构建、3 项音频单测通过。生产 / 开发浏览器完整回归分别通过 13 / 17 项，之后加入服务重启清理旧场景用例，两种模式的 3 项场景测试再次通过。CI 运行完整套件并上传报告。

Ubuntu 浏览器回归暴露软件 GPU 下状态显示滞后（重置 HTTP 约 45 ms 返回，页面结果超过 5 秒仍未更新）。最终处理包括软件渲染器降画质、绘制后空闲间隔、重置复用几何和每次确认后发送最新状态，避免旧快照积压。本机 Chrome 显式使用 SwiftShader 的 3 项场景测试全部通过，完整物理交互用例约 36 秒；开发模式同样通过 3 项场景回归。16 项物理后端测试含慢客户端、非法确认帧、确认超时、几何复用，接触成功条件没有放宽。

## 未验证与限制

- 真实服务只做了有限轮次联调，尚未完成连续十轮、真人口音、嘈杂环境、远场拾音或长期稳定性测试；未核对账单中的具体消耗。
- 没有实体机器人、舵机、电池或麦克风板，不能宣称完成硬件复刻。
- 原工作台的三维形象是原创示意；robotd 路径的物理结果来自独立官方 MuJoCo 进程。物理实验室则由 Python 进程中的 MuJoCo 提供实时官方模型姿态，三条路径独立标识。
- 物理实验室使用官方 MJCF 的位置执行器，没有校准到实体电机或接入动态 BAM 模型；接触和位移只对当前仿真设置成立。
- 定点踢球会先摆球，不会自主寻找或追球。双鸭感知使用仿真真值与视线条件，不是视觉识别或实际无线发现。合唱是本地双声部合成，不是官方 BLE 合唱或云端歌声。
- 不提供唤醒词、全双工、精确距离导航或生产环境公网部署。
- 默认音频交互是按键半双工，录音最长 15 秒；断线后手动重连。
- 当前只有一个实际提交账号；多人协作机制已建好，真实多人贡献仍需队员参与。
- 使用软件仿真替代实体作品是否合题，需要主办方确认。
