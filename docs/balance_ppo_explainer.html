0. 预备知识：RL 和 PPO 到底在解决什么问题

本节要先建立四个认知，后面所有公式都建立在它们之上：
① 强化学习解决的是没有标准答案的问题——它的学习信号是打分，不是标签；
② PPO 属于"策略梯度"家族，核心机制是每次更新只允许策略改动一点点；
③ 后文出现的每个量（状态、动作、奖励、优势、裁剪），在这一节里都有通用定义；
④ 本项目没有发明新算法，只是把教科书上的 PPO 套进了一个具体的转盘物理问题里。

0.1 起点：为什么这件事不能用监督学习做

你大概率学过监督学习：训练数据里带着标准答案（标签），模型学的就是 "从输入映射到答案"这个函数。损失函数直接告诉你错多少，梯度方向清清楚楚。

但转盘平衡这件事没有标准答案。在这个 25 维观测空间的任何一个点上， "此刻该使多大的力"都无法人工标注——那需要同时理解盘面倾角、自转相位、身体姿态、 接触摩擦和官方步态的脾气。理论上可以标注少量轨迹，但覆盖度远远不够。

于是换一条路：做一次动作，看结果，给个分数，再调整下次的倾向。 这就是强化学习。它比监督学习难在三点：

  1. 信号更弱。标签直接说"对/错"，奖励只说"这一步好不好"，而且这个"好"往往是延迟兑现的。
  2. 必须自己探索。没走过的路不知道好不好，所以要一边按当前认知走、一边留出余量去试新的 （这就是探索 vs 利用的取舍，后面"熵"那一项就是它的量化）。
  3. 优化对象是概率分布，不是数值。监督学习可以直接对输出求误差；RL 里要动的是 "在状态 s 下选动作 a 的概率"，动完还要重新采样，链条更绕。

0.2 术语与 MDP：RL 的标准设定

RL 有一套装配得非常统一的术语，初学者觉得别扭，多半是因为没记住它们各自的角色。 两个角色：智能体（agent）负责决策，环境（environment）负责执行动作并给反馈。 二者交替进行，串起来就是一条轨迹（trajectory）。

状态 s：智能体此刻能"看见"的全部信息
动作 a：智能体此刻输出的一个决定
奖励 r：环境对这一步的即时评价（一个标量）
转移：环境按 P(s′|s,a) 把下一状态 s′ 随机地定下来
折扣因子 γ：未来的奖励在总分里打几折
"马尔可夫"是这套理论能跑起来的关键。它要求：下一步的结果只取决于当前状态 s 和动作 a， 与更早的历史无关。这不是数学家的浪漫想象，而是物理系统的真实性质—— 圆盘转盘的下一时刻由此刻的位姿和速度决定，不取决于它三秒前是怎么转过来的。 正因为如此，价值函数 V(s) 才只需要看当前这一步，而不必翻阅整段历史。

0.3 目标：累积回报与"打折"

RL 不追求"这一步最高分"，而是追求整条轨迹的累积回报：

Gt = rt+1 + γ·rt+2 + γ²·rt+3 + γ³·rt+4 + …
// 训练的目标就是让 E[Gt] 尽可能大

为什么要打折（γ < 1）？三个理由：① 未来的事不确定，越远越该保守； ② 保证收敛——γ=1 时无限长的奖励序列没有上界，回报可能发散； ③ 符合直觉——十秒后的收益比眼前的收益"轻"一些。 本项目取 γ = 0.995：

γ10 ≈ 0.951　　γ50 ≈ 0.778　　γ100 ≈ 0.606
// 也就是说：50 步之外的奖励只剩约 78% 的分量，100 步之外只剩约 61%

0.4 三个核心函数：策略、价值、优势

这三个函数是理解 PPO 的钥匙。它们各自回答一个问题：

函数回答的问题定义
策略 π(a|s)"在状态 s 下，我该选动作 a 的概率是多少？" 一个从状态到动作概率分布的映射。这就是我们训练的东西——训练完导出的就是它的参数。
价值 V(s)"我现在这个状态，未来大概能拿多少分？" V(s) = E[Gt | st = s]，即未来回报的期望。它是辅助的，训练完就丢掉。
优势 A(s,a)"选这个动作，比'随便选一个'好多少？" A(s,a) = Q(s,a) − V(s)。V(s) 是"平均分"，Q(s,a) 是"选这个动作能拿多少分"，两者之差就是超额部分。
PPO 的一句话概括：把优势为正的动作概率往上推，把优势为负的往下压， 但每次只推一点点。后面所有公式，都是这句话的展开。

0.5 学习方法：策略梯度

既然要动的是概率分布，最直接的办法就是对策略参数求梯度。 策略梯度定理告诉我们，这个梯度可以这样估计：

∇θ J(θ) ≈ Et[ ∇θ log πθ(at|st) · A(st,at) ]

拆开看：∇θ log π(a|s) 描述"把动作 a 的概率往上推，概率会增加多少"； A 决定"该不该往上推"——为正就推，为负就反向压。两者相乘求平均，就是一次更新方向。

0.6 为什么不能照着普通随机梯度下降做

朴素策略梯度有三个现实麻烦：

  1. 样本效率低。每采一条轨迹就用一次，梯度估计噪声极大，要浪费掉海量样本。
  2. 步长极其敏感。θ 稍微动一下，采样出来的动作分布可能整个变样， 于是"这次学到的经验"和"下次的策略"对不上号。
  3. 数据高度相关。连续采样得到的状态彼此很像，不能当成独立样本， 直接算均值会让方差被严重低估。

PPO 的折中方案是：采一大批数据，然后反复用它更新（本项目是 256 步 × 2 环境， 然后重复更新 10 遍）。这大幅提升了样本效率。但代价来了——第 10 遍更新时， 策略已经离采样时的策略相当远，那批旧经验就不再代表当前策略了。 所以必须回答一个问题：一次更新最多允许策略改变多少？

TRPO： 限制 KL(π_old ‖ π_new) ≤ δ　　// 真信赖域，理论上更稳
PPO： 用"概率比裁剪"来近似这个限制　　// 一阶方法，实现简单，效果接近

0.7 PPO 的裁剪目标：安全阀的具体形状

设 r̂ 为概率比——新策略给某动作的概率除以旧策略给它的概率：

r̂t = πθ(at|st) ⁄ πold(at|st)
Lclip = Et[ min( r̂t·At , clip(r̂t, 1−ε, 1+ε)·At ) ]
// ε = 0.2，即 r̂ 被限制在 [0.8, 1.2]

分两种情况读这个公式：

  • A > 0（这是个好动作）：目标值随 r̂ 上升，直到 r̂ = 1.2 封顶。 也就是说——不鼓励把一个好动作的概率推得更猛，因为一旦推过头， 旧数据就不再代表新策略了。
  • A < 0（这是个坏动作）：r̂ 低于 0.8 之后目标值封底， 不再奖励"进一步压低这个坏动作的概率"。
一个诚实的细节：图 5 里红线右端是继续往下走的——当 r̂ > 1.2 且 A < 0 时， 裁剪并没有给出下限。这是 PPO 公认的非对称之处。实践中由 ε、学习率和多轮 epoch 共同把改动幅度压住， 但如果你以后看到"PPO 把坏动作压过头"的现象，根源就在这里。

0.8 优势从哪来：GAE 的一句话版

前面说 PPO 要用优势 A，但优势怎么算？最直接的算法叫 TD 误差：

δt = rt + γ·V(st+1) − V(st)
// 读法：这一步实际拿到 r，再补上"下一步大概还能拿多少"，减去"我原本以为能拿多少"
// δ 就是"比预期好多少"，把 δ 沿轨迹累加，就得到优势 A

问题是：只用一步的 δ 噪声大，只用整条轨迹的 δ 又太迟钝。 GAE（广义优势估计）在两者之间做指数加权，本项目取 λ = 0.95。 完整推导和参数含义见 第 8 节。

1. 先说清楚：我们在做什么

一句话：机器人的脚踩在一个会倾斜、还会自转的圆盘上，怎么学会不摔下去。
训练出来的到底是什么：一个 25→64→64→3 的小神经网络（约 6 千个参数）， 它的输出不是关节角度，而是三个"该往哪边使多大劲"的力度数字。

这可能和你在教科书里见到的"机械臂抓杯子"不一样，有三点需要先建立直觉：

  1. 不是从零学走路。鸭子本来就会走——那是 Pollen Robotics 官方训练好的 velstand.onnx 步态策略，我们把它冻结（不改一个参数）。 我们新训练的只是"站在转盘上该怎么使力"这一层。
  2. 不是视觉。策略看到的 25 个数字全部来自仿真引擎的真值（位置、速度、角度）， 不是摄像头画面。这让实验可复现，但离"真机自主平衡"还有距离。
  3. 动作空间被刻意做窄了。策略不能直接命令关节，只能输出三个非负的"力度"。 把"往哪走"这件事用一条手写的工程先验固定住， 让 PPO 只负责学一件事：什么时候该使多大力、什么时候该收。

这条"窄动作空间 + 手写反馈律 + 冻结底层步态"的结构，是整个实验能在一台笔记本 CPU 上 几十分钟跑完、并且结果可复现的根本原因。下面逐层拆开。

2. 转盘是什么：三个关卡的物理

圆盘不是"贴图动画"，它在 MuJoCo 里是一个有真实质量（2 kg）、惯量和有限执行器力矩的刚体， 由三个铰链叠成：roll（绕 X 轴倾斜）、pitch（绕 Y 轴倾斜）、 spin（绕 Z 轴自转）。倾斜执行器 kp=120, kv=10, ±25 N·m， 自转执行器 kv=8, ±12 N·m——力矩是有限的， 所以"让盘子转到目标角度"是一个需要时间的过程，而不是瞬间到位。

盘面目标运动是随时间连续变化的正弦叠加，再乘一个"加速—保持—减速"的包络， 最后每步还要做速率限幅（每 5 ms 最多改变 0.12 rad / 0.12 rad / 1.2 rad/s）， 所以即使中途喊停，盘子也会平滑地慢下来。

关卡任务目标转速上限每轴倾角上限起始离心距离
1 跟着圆盘站稳可以随盘改变朝向，但要在盘上、留在中心区9 RPM3°1.875 – 2.5 cm
2 转盘转，我不转保持世界正前方朝向，允许迈步12 RPM4°1.875 – 2.5 cm
3 从边缘回到中心从偏心位置回到中心，保持朝向10 RPM5°12 – 16 cm

这些是目标值的上限，实际转速与倾角来自动力学过程，存在跟踪误差；不是硬件安全转速认证。随机化内容包括：三个波形初相位、顺/逆转向、盘面摩擦系数（0.8–1.1）、起始位置与小幅朝向偏差。

3. 强化学习的最小骨架

第 0 节已经把强化学习的通用术语和算法原理讲完了。这里只做一件事： 把那些抽象名词逐一换成 DuckKing 的具体实物—— 看状态 → 选动作 → 拿到分数 → 更新"下次怎么选"。 没有 AI 背景的话，把它当成一个带反馈的打分游戏就够了。

状态 s：策略此刻能"看见"的全部信息（本项目是一个 25 维向量）
动作 a：策略此刻输出的决定（本项目是 3 个力度数字）
奖励 r：环境对这一步的评价（一个标量，越大越好）
策略 π(a | s)：给定状态该选什么动作的函数 —— 我们训练的就是它
价值网络 V(s)：对"从这个状态出发，未来大概能拿多少分"的估计 —— 辅助用的
为什么需要价值网络？因为奖励是"延迟"的：现在踩一步不一定立刻加分， 但可能让十步之后少摔一次。价值网络给每个状态打个"未来收益分"， 这样"这一步比预期好多少"就能算出来——这个差值叫优势（advantage）， 是 PPO 更新策略的真正依据。

4. 三个频率：为什么这样分层

这是整个设计里最值得学的一点。现代机器人系统几乎都是多频率分层： 慢的控制决策 + 快的物理仿真 + 中间的底层策略。

一个任务步 = 0.1 秒（10 Hz）
　└─ 物理 20 个小步 × 5 ms = 0.1 秒　（MuJoCo 200 Hz）
　└─ 官方步态推理 5 次 × 20 ms = 0.1 秒　（velstand.onnx 50 Hz）
　└─ PPO 决策 1 次 = 0.1 秒　（10 Hz）

为什么不让 PPO 每 5 ms 决策一次？三个理由：

  • 算力：每步都要跑一次神经网络 + 一次 ONNX 推理 + 20 次物理积分。 放到 200 Hz 会让采样成本翻 20 倍，而同样的样本量根本学不出差别。
  • 信噪比：动作频率越高，连续两步之间的效果差异越小， "这一步好不好"的估计噪声越大。
  • 物理上也没必要：0.1 秒内人感觉不到差别，而且这 0.1 秒里 真正维持平衡的是冻结的官方步态——它本来就是 50 Hz 训练的。

5. 观测：策略能"看见"什么

观测就是喂进策略网络的输入向量，一共 25 维。挑这几个量的原则是：够用来判断"我该往哪使劲"， 且每一维都有明确物理含义。

维数内容为什么这样表示作用
2指向盘心的位移 e把鸭子的位置换到身体朝向的坐标系里，再除以 10 cm 归一化知道“我偏了多少”
2身体朝向 sinψ, cosψ用 sin/cos 而不是角度本身，避免 180° 处跳变知道“我朝哪”
3投影重力身体竖直轴在世界坐标的分量取负知道“我歪了没、往哪边倒”
6身体角速度 + 线速度3 个角速度 + 3 个线速度知道“我在怎么转、怎么飘”
2圆盘两轴倾角roll 与 pitch 的实际角度知道“盘子在往哪边倾”
3圆盘三轴角速度roll / pitch / spin 的角速度知道“盘子转多快”
2支撑数与高度接触脚数 ÷2、相对盘面高度 ÷15 cm知道“我还站得住吗”

两个值得学的工程细节：
① 朝向用 sinψ, cosψ 而不是角度本身——因为 179° 和 −181° 是几乎同一个方向， 但数值上差了 360°，直接喂给网络会造成不连续。
② 时间比例（已用时间 ÷ 总时长）必须进观测，否则策略分不清"现在是加速冲刺阶段"还是"该收尾减速了"。

6. 动作：策略其实只能调"力度"

这是本项目最关键的设计决策，也是它区别于普通 RL 机器人的地方。

策略网络输出 a ∈ [−1, 1]³，但它不直接代表速度。 先取正部当作"力度"：

g = max(a, 0),   a ∈ [−1, 1]
// 下面这条反馈律是手写的工程先验，不是学出来的
v前后 = clip( 3 · g₁ · e前后 , −0.18, 0.18 ) m/s
v横移 = clip( 3 · g₂ · e横移 , −0.12, 0.12 ) m/s
ω转向 = clip( −g₃ · ( 4 · ψ + 1.5 · ω盘 ) , −1.8, 1.8 ) rad/s

其中 e 是"指向世界 XY 盘心、按身体偏航角旋转后的水平位移"， ψ 是身体朝向误差，ω盘 是圆盘自转角速度。 第 1 关的转向项恒为 0。

速度指令还要再过一次变化率限幅，否则策略输出抖一下，关节就会猛抖：

每步最多改变：0.08 m/s（前后）、0.06 m/s（横移）、0.6 rad/s（转向）
请注意这里的设计取舍。PPO 学到的是"什么时候该使多大力"， "往哪走"是手写的。所以：
● 好处：任务空间极小（3 维力度），几万次采样就能学到东西，结果可解释、可复现；
● 代价：它学不到"绕过障碍物"这类需要自主规划的行为，只能在给定反馈律的框架内调节强度；
● 边界：没有给鸭子的自由根加力、没有焊脚、 没有在运行中改写根位置——所有运动都真的经过官方步态和 MuJoCo 接触。

7. 奖励：八个分量怎么打分

奖励是训练里最"需要工程直觉"的部分。设计原则：每一项都要对应一个我们真正关心的行为， 而不是随便堆一堆指标。

rt = wupright·直立度 + wcenter·exp(−(r/0.10)²) + wheading·exp(−(Δψ/0.35)²)
　　　+ wprogress·(rprev − rnow)/Δt − wslip·滑速 − wsmooth·Δa²
　　　− wfall·[摔倒] + wsuccess·[全程达标]
分量权重公式意图备注
upright1.0× 直立度站得越直越高分≥0.65 视为没倒
center2.0× exp(−(r/0.10)²)越靠近盘心越高分（高斯衰减）r 是离盘心距离
heading1.0× exp(−(Δψ/0.35)²)朝向越正越高分第 1 关为 0
progress8.0× (r_prev − r_now)/0.1回报制：这一步让离盘心近了多少权重最大，鼓励持续向心
slip0.15− × 脚底滑速脚在盘面上打滑要扣分滑速＝脚与盘面同接触点的相对切向速度
smooth0.025− × 动作变化²抑制动作抖动让动作更平稳
fall10.0− 一次性摔倒重罚任何跌倒或越界立刻判负
success20.0+ 一次性全程达标额外奖励10 秒扰动 + 3 秒减速全部完成
"progress" 是回报制（reward shaping）里最有代表性的一招。 它不给"离中心近"这个状态本身打分，而是给"这一步比上一步近了 3 厘米"打分。 好处：不会鼓励策略"停在原地刷分"，因为站着不动 progress 就是 0； 而且和"中心"项不冲突——前者鼓励过程，后者鼓励状态。
权重 8.0 是八项里最大的，说明"持续向心移动"是这项任务最主要的难点。

成功判定比奖励更严格，是一套独立的物理验收条件（不是看奖励够不够）：

  • 全程无躯干/非脚部触盘、无落地；脚的保守包围盒不越过盘缘
  • 躯干直立度 ≥ 0.65、相对盘面高度 ≥ 7.5 cm；连续无脚部支撑不超过 0.4 秒
  • 结尾距中心 < 8 cm，并连续保持至少 1 秒
  • 实际盘速 < 0.25 RPM，两轴实际倾角绝对值 < 1°（盘确实停了）
  • 第 2、3 关：至少 85% 的任务步朝向误差 < 25°

8. PPO 到底在优化什么

PPO（Proximal Policy Optimization）是最常用的 RL 算法之一。它的核心卖点是： 每次更新只允许策略改动一点点，这样训练过程不会突然崩溃。

它的完整推导链条（策略梯度 → 信赖域 → 裁剪目标 → GAE）在 第 0 节 0.5–0.8 已经铺垫过了。本节只做两件事： ① 把每个公式落到本项目的具体数值上；② 给出这次训练真正使用的超参数。

8.1 优势：这一步比"平均预期"好多少

即时优势： At = rt + γ·V(st+1) − V(st)
// 用 GAE 折中，得到更稳的优势估计：
δt = rt + γ·V(st+1) − V(st)
AtGAE = δt + γλ·δt+1 + (γλ)²·δt+2 + …

直觉：δ 是"实际比预期多拿/少拿的分"，A 把它往后累积几步。 λ=0.95 意味着几乎看完整条轨迹，但每一步的影响按 0.95 衰减—— 既比只看一步稳，又比看完整条轨迹反应快。

8.2 裁剪目标：PPO 的安全阀

Lclip = Et[ min( r̂t·At , clip(r̂t, 1−ε, 1+ε)·At ) ]
// r̂ = 新旧策略的概率比；ε = 0.2

若旧策略认为动作 a 的概率是 p，新策略变成 p′，则 r̂ = p′/p。 裁剪的意思是：一旦 r̂ 超出 [0.8, 1.2]，就不再鼓励继续加大这个动作的概率。 效果类似"每次只挪一小步"，避免一次更新把策略推到完全不同的行为上。

8.3 一次更新长什么样

总损失 = 策略损失 − cent·熵 + cvf·价值损失
// 熵项鼓励策略保持一定随机性；价值损失让 V(s) 逼近真实回报

9. 完整训练流程与验收口径

三个设计上的"防作弊"机制，值得单独学：
① 验证种子与测试种子完全分开：验证固定用 [1 000 000, 1 000 020)， 最终测试用 [2 000 000, 2 000 100)。选策略只能用验证集，测试集在最后才碰一次。
② 配对基线测试：最终测试时，用同一批 100 个种子再跑一遍"零动作策略"。 这样"策略 vs 基线"的对比控制了全部随机性差异，是真正的配对实验。
③ 门槛要求连续两次：单次达标不算数，要连续两个不同检查点各 ≥18/20。 即便如此，这只是工程上的"稳定"判据，不是数学意义上的收敛证明。

9.1 导出的策略是一份可审计的 JSON

训练完不只留一个黑盒 checkpoint，而是导出成纯数值的 JSON（层权重 + 偏置）， 并且用 32 组随机输入核对导出后的 NumPy 推理与 SB3 的输出是否一致 （rtol=1e-5, atol=2e-6）。服务只加载数值 JSON，不反序列化观众提交的 pickle。

9.2 成功的置信区间

Wilson 95% 区间：
中心 = (p + z²/2n) / (1 + z²/n)， 半宽 = z·√( p(1−p)/n + z²/4n² ) / (1 + z²/n)，z = 1.96

小样本（比如 20 回合）用简单的"比例 ± 误差"会给出荒谬的范围，Wilson 区间在小样本下更可靠。

11. 诚实的边界

  • 第一关不能算成绩。官方基线就是 100/100，PPO 没有新增能力。
  • 只跑了一个训练 seed（42）。单个 seed 的结果不足以证明跨训练 seed 的稳健性。
  • "未见种子"仍在同一物理分布内。没有验证更高转速、新质量分布、真实机器人或新的摩擦范围。
  • 第三关还不稳定（最佳 55%），不能按可靠通关能力介绍。
  • 观测是仿真真值，不是摄像头。没有做过视觉输入或域随机化的视觉鲁棒性实验。
  • 奖励缩放 0.05 只影响优化的数值尺度，所有指标曲线仍是原始单位——不要把缩放后的数值当成绩。
  • 接触判定有明确口径：脚部支撑按官方脚部刚体归属识别；滑速是脚与运动盘面同一接触点的相对切向速度；整脚边缘检查用碰撞网格的保守包围盒，不只看躯干中心。
  • 速度坐标系不能混用：身体速度用 MuJoCo 普通刚体坐标系 mjOBJ_XBODY； 把惯性坐标系 mjOBJ_BODY 的速度和 xpos 的力臂混用会算错偏移——这是一个真实踩过的坑。
  • 连续两次达标不是收敛证明，两次检查点也不能当成 40 个独立样本。
