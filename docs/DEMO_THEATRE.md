入口为 `demos.html`，首页导航中的“演示场景”可打开。当前共十三幕：最初十幕，随后增加桌上跌落、坐姿独唱和四鸭发布会。当前画面见 [四鸭合唱截图](media/theatre-current.png)。点选节目就会准备场景、播放台词、执行动作并检查结果，无需真人讲话。Esc 或“停止演示”取消当前脚本、音频与物理动作；再次点选从场景初始布置重演。

## 三份方案的评估与取舍

评估输入为用户提供的三份本地报告：`DEMO_SCENARIOS_0.md`、`DEMO_SCENARIOS_1.md`、`MicroDuck 黑客松 演示场景设计.md`。每份五幕，名义上共十五幕，但搬运、打断和双鸭相遇重复，不能算十五种独立能力。以下是针对本次实现的主观评估，不是评委打分或实测数据。

- **方案 0** 擅长展示工程完成度，搬运、隔离、打断有现有能力支撑。自动演示时，“评委手机隔空指挥”失去现场参与的主要亮点。报告描述的自主张望搜索并不是原 `find_companion` 动作的能力，需要显式增加有界转向。
- **方案 1** 身份、声音与合奏的想象力最强，但音色克隆、vetbook 实机记录、即时生成动作与 BLE 合唱仍有实现缺口。不能把灵矽产品的目标延迟当作本项目实测，也不能把本地共享音频时钟说成完成了无线时钟同步。
- **故事方案** 最适合路演：招聘、甲方、世界杯、交付、出道各有生活化笑点，物理结果决定剧情能否继续。自动版用预录指令替代现场变量，并明确标注来源。

## 两种自动语音方式

默认“自动演示 · 预录对白”使用固定本地剧本和实时 MuJoCo，台词不是灵矽回答。切换到“灵矽实连 · 预录指令”后，节目中的指令 WAV 按 16kHz / 60ms / PCM16 帧发送给已有灵矽会话，实际 STT、MCP 和 TTS 来自当轮云端。两种方式均无需麦克风权限；第一次点击节目会解锁浏览器声音。移动浏览器仍需媒体音量正常并保持页面前台。

旁白与趣味台词在两种方式中均是预录角色音频，页面始终区分“预录旁白 / 角色台词 / 指令”和“灵矽实时回答”。人类指令与旁白由 macOS Tingting 合成，小鸭使用 Eddy 中文音色，升调 14% 并做轻量滤波，保持原语速；页面提供分别试听。可运行 `uv run python scripts/build_demo_audio.py` 重新生成；生成结果随发布包携带，Linux 运行不依赖 macOS 或 ffmpeg。每句 PCM 限 15 秒。

云端模式会检查本轮真正执行的动作列表；允许灵矽在动作前显式准备一次当前场景，这一步仍保留在记录中。缺少、额外或失败的动作、切换到其他场景、动作中途重新布置场景都会明确停止，不用本地动作补造云端成功。场景布置、取证和第 10 / 11 / 12 幕音乐演出仍是应用编排，这三幕在实连模式下也明确标记为本地音乐，不冒充灵矽生成的歌曲。第 7 幕需要两个空闲房间，会拒绝占用另一位用户正在使用的房间。两间房的云端动作独立，网络和模型响应时间可能不同，不能保证两段舞步同步起拍。

## 四声部究竟是什么效果

四声部是同时演唱不同音符的 bass / tenor / alto / soprano，分别为低音、次中音、中音、高音。官方 `wistful` 开头逐层叠入 C3、G3、C4、E4，听起来是和声逐渐变厚；不是四遍相同录音，也不是四只鸭轮流讲话。

本页取固定官方谱面开头 16 拍（58 BPM，约 16.6 秒），本地 Web Audio 合成音色。先由 A / B 演唱低音与高音，第 4 拍加入虚拟 C 的中音，第 8 拍加入虚拟 D 的次中音，第 13 拍 C 离开，其席位保留、声部静音。A / B 是舞台中的 MuJoCo 实例；C / D 是附加的音乐声部，没有伪装成四鸭物理仿真。谱面原文件与 Apache-2.0 许可随页面提供。

复现范围是初始按声区排序、固定最低演示 ID 指挥、新成员补空缺声部、离开留席。未接真实 SoC 标识，未移植官方音色合成器，未实现 BLE 广播、独立板级时钟、相位平均或 ±20ms 无线同步验收。浏览器使用一个 AudioContext 排程；声部卡和拍数展示音乐调度，不是无线测量结果。

官方参考：[chorale 说明](https://github.com/pollen-robotics/microduck/blob/942e58e3aa6dbb28e7037203fff11866122c7567/docs/robot/cheatsheet.md#the-duck-chorale)、[声部规则](https://github.com/pollen-robotics/microduck/blob/942e58e3aa6dbb28e7037203fff11866122c7567/sounds/src/chorale/mod.rs)、[wistful 乐谱](https://github.com/pollen-robotics/microduck/blob/942e58e3aa6dbb28e7037203fff11866122c7567/sounds/scores/wistful.duckscore)。

## 运行与实现边界

模型来自官方固定版本，舞台的位置、碰撞、夹持与球位移来自实时 MuJoCo；不是播放物理录像。新增 `.dkm.gz` 场景资源无损压缩网格，页面按模型 revision 缓存，重置动态状态无需重复下载。原物理实验室接口保持兼容。

单幕最多是有限个现有有界动作。切换、停止、页面退出会取消本页脚本、清空音频并请求停止其使用的房间；程序异常、云端断线、模型加载失败都不切换到动画预览。嘴部实验仍限固定轻棒；寻友是预先编排的有限转向和真实视域检测，不是自主探索或摄像头识别。四声部的本地合成与灵矽语音严格分开标识。该项目仍未完成实体硬件复刻或实机验收。


## 第十一幕：桌上不掉拍

四只官方 MicroDuck 同在一张 90×104 cm、40 cm 高的有限桌面上。36 秒音乐期间每四拍交替踏步和站立摇摆；踏步向官方策略发送有界速度，以位置反馈保持站位，行走时清零身体姿态意图，不写入根位姿或关节动画。第 16 秒起鸭 D 进行最长 3 秒的向前步态，离开桌沿后由真实接触和重力决定跌落。它离桌、触地后，其他三只短暂停顿再继续；D 在地面保持直立至少 0.4 秒后，基于实际落地位置与朝向恢复交替踏步和摇摆，末尾说“我没掉队，只是把低音部，搬到了楼下”。这段失足时机是预先编排的笑点，不是自主决策或实体机器人跌落测试。

节目单提供三种一键开演版本：

- 《欢乐颂》：Mutopia 公共领域 SATB 谱前八小节重复一次，108 BPM、64 拍。四条独立声部；鸭 D 的高音主旋律较突出，实际跌落时短暂缺席，落地后恢复。
- 《两只老虎》：传统《Frère Jacques》旋律，108 BPM，四鸭间隔 8 拍依次入唱，分别在 0 / 4.44 / 8.89 / 13.33 秒进入；高低八度和左右声像帮助区分，最后四拍统一收尾。本地电子合成音色，不含演唱歌词。
- 《夜空中最亮的星》：默认保留用户提供的人声片段。鸭 D 承担原主唱混音（增益 .42），A / B / C 分别突出低八度、齐唱、高八度鸭声（.30 / .28 / .28）；鸭声在变调、滤波后先按 −16 LUFS 重新配平，再应用上述增益，避免只放大控制数值而实际仍被人声盖住。主唱居中，真实跌落时短暂收声，落地后恢复。35.2 秒原片段在 34.1—35.2 秒淡出，补齐至 36 秒。伴奏仍包含在各层中，不是分离纯人声或独立 SATB 编曲。

高级设置保留原人声、器乐、独立原创练声曲《桌边的星光》。后者与《夜空中最亮的星》的旋律无关，界面明确区分。声部共用一个 AudioContext，音乐与编排同起播；72 BPM 是动作编排节奏，与合成曲目的 108 BPM 构成 2:3 关系，不宣称步态每一步精确踩拍、歌曲节拍提取或歌词对口型。完整混音模式只能整体收声与加入失足提示音。

也可选择本机一份混音或四份按 A—D 排列的音轨，并指定起播秒数。音频留在浏览器，不上传；每份不超过 25 MB、合计不超过 40 MB，解码样本总数也有上限，起点之后须有完整 36 秒。音源缺失、损坏、时长不足、声音时钟暂停或物理结果失败会明确停止，不暗中换歌。内置素材由 `scripts/build_table_music.py --vocal <人声文件> --instrumental <器乐文件>` 离线生成，来源摘要和处理方式在 `frontend/public/demo-music/manifest.json`；原作品权利仍归原权利方，不受本仓库 MIT 许可覆盖。

物理验收要求：鸭 D 躯干实际低于桌面且失去支撑，随后检测到地面接触；其余三只仍受桌面支撑且未接触地面。不会以播放进度代替物理结果。停止/换幕取消整段编排并清空四条音乐源；清零意图不会冻结重力。桌面模型首次使用时才编译，复用官方几何的重复数据块，四鸭模型无需传输四份相同网格。

默认镜头在开唱时靠近舞步；检测到实际跌落后，根据四鸭位置扩大视野，保留脚部和标签边距，避免手机宽度下裁掉地上的鸭子。D 站稳起舞后重新取景，让地面踏步也容易看清。用户主动旋转或缩放后停止自动取景；“复位视角”恢复默认取景。


## 第十二幕：轮到我开唱

四只鸭先坐稳，合唱《欢乐颂》开头；随后按 A、B、C、D 分句接唱。轮到的鸭子实际站稳才开始独唱，唱完坐回，其他鸭子保持坐姿。独唱期间只有该鸭发声，起身和坐回的过渡段有轻声和声，最后全体坐着合唱收尾。音乐 40 秒，加上就座和模型准备约 45 秒。

本幕是本地合成曲目与真实 MuJoCo 坐站编排，两种全局模式下均明确显示“本地音乐 + 物理编排”。《欢乐颂》谱面沿用 Public Domain 的 Peter Chubb 版本，四段主旋律分给四鸭，低 / 高八度区分声区。没有新增或冒充灵矽实时歌声。

每只鸭都记录独唱前的站稳数据、唱后的坐稳数据，以及全程桌面 / 地面接触和最大偏移。停止音乐时取消未来轮次，回到最近确认的稳定姿势；只有四次交接全部实测完成才显示成功。单鸭 / 双鸭的手动坐站入口在物理实验室，首页动画预览没有该动作。


## 第十三幕：黄仁勋的四只小鸭

GTC MicroDuck 舞台互动的中文改编，来源为 [NVIDIA 官方纪要](https://blogs.nvidia.com/blog/gtc-berlin-2026-keynote/)。本幕复用固定官方模型、ONNX 策略与近似嘴部铰链；不代表 NVIDIA 授权或原现场控制系统复现。三段人类指令由 macOS Tingting 合成，来源记录在音频 manifest，不模仿黄仁勋音色。

四只鸭在同一个地面物理世界中随机散落，初始位置不重叠；按横向位置分配 A—D，随机种子随实际结果返回便于排查。收到召集后，用仿真位置反馈和有界 A* 绕行走向各自站位，行走途中错开时间打哈欠；头嘴为本地表情，腿部为官方策略。位置与关节仅在显式重置时初始化，集结不传送、不修改根坐标。

真实鸭鸭接触可以触发一次剧情反应：随机选择碰撞双方之一，坐稳、短暂停顿、站稳后继续。它是“碰撞触发坐下”的编排，不是碰撞力必然把鸭子撞成坐姿；避让成功时不会强造碰撞。任务失败或越界、失稳、超时会明确停止。

自动模式依次执行集结后坐下、四鸭起身后选中鸭同时前滚翻并就地坐下（未点选时自动模式演示 A；一旦操作选择便使用所选集合）、选中鸭站起后同拍闪身步与抖毛。选中鸭的齐舞共享 MuJoCo 仿真时钟，不是四次网络指令同步，也不宣称四只实体机器人的无线同步精度。实际身体受接触与策略影响，不能保证逐关节姿态完全相同。

节目单上将“第13幕演出操作”改成“现场互动”后再点本幕，可使用本地按钮或连接真人灵矽语音。点鸭子／指挥棒切换选中或取消，可多选；每只选中鸭显示独立光圈，勾选框提供键盘与手机替代。“这只／这些”使用整个选中集合，“最左边”在录音开始时按屏幕投影顺序更新并锁定到本轮目标。拖动仍旋转镜头。轻戳为固定 1 N、0.08 仿真秒的躯干外力，不保证跌倒；释放或取消必清空外力，轻戳后重新集结。

灵矽提供按 member 指定的召集、点名翻滚、齐舞和停止/状态工具；集结与翻滚都等待真实结果，不允许换场景重置来补造成功。部署新工具后重新连接语音；同步专用提示词仍走显式 `duckking-setup --sync-prompt` 流程。当前实现不接入官方 robotd 路径，也没有实体机或真人麦克风的新验收记录。

多鸭翻滚先让四鸭站稳，选中鸭在一个任务里同拍启动，每只分别确认翻转和站稳后就地坐下；未选中鸭站着候场。齐舞仅让选中鸭起身表演，不改变其他鸭的坐站姿态。空集合明确提示选择，不回退到 A。自动剧本与本地按钮均使用当前选中集合；语音开始时冻结本轮集合，后续点击只影响下一次命令。

第十三幕自动表演完成后保留当前舞台、选择和操作会话，三个本地按钮可反复操作。再次集结先让选中鸭起身、走回其队列位置再坐下；未选择时召集四鸭。翻滚和齐舞可以直接从当前稳定坐姿或站姿开始，不要求先回到队列。停止／换幕／离开页面才清理操作会话，不把后续本地操作记成自动或云端演出成功。
