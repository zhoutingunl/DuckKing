# 商业价值与产品设计

更新于 2026-10-27。本文依据当前实现描述产品，并将下一步设计与商业假设单独标注。技术实现见 [架构与模块规格](ARCHITECTURE.md)，具体测试证据以 [验证记录](VALIDATION.md)绑定的提交为准。

## 1. 产品定位：购买硬件前的体验窗口

**DuckKing 让用户不用先购买 MicroDuck，也能在浏览器里了解它的部分动作能力，亲自体验通过灵矽语音指挥仿真小鸭。** 用户可以先看演出，再自己发出命令、改变动作顺序，判断这种互动是否有趣、是否适合自己的用途。

截至 2026-10-27，官方公布的 MicroDuck 预售价为 **399 美元，未含税费和运费**。这给购买前试用提供了现实动机，但不能据此断言所有消费者的支付能力或购买意愿；本文没有市场规模、销量或用户调研数据。[官方产品页](https://pollen-robotics.com/microduck/) · [官方商店价格说明](https://store.pollen-robotics.com/products/microduck)

围绕竞赛题目“智能硬件：复刻一台 Micro Duck，并在其内装上灵矽通过语音交互”，当前交付的是语音接入、动作控制、仿真反馈与体验统计的软件原型。灵矽真实连接运行在 DuckKing 服务端；没有完成实体复刻、在实机内安装灵矽或实机验收。浏览器体验不能替代对实物声音、触感、续航、运动稳定性和长期可靠性的检查。

## 2. 用户与问题

| 优先级 / 用户 | 想解决的问题 | 当前提供的入口 |
|---|---|---|
| 第一：对 MicroDuck 感兴趣、尚未购买的人 | 视频很有趣，但不清楚自己会怎么玩、语音能控制到什么程度 | 浏览器自动演示、真人语音、动作按钮和结果反馈 |
| 第二：准备做二次开发的爱好者、开发者 | 想先判断如何把语音、动作与自己的玩法连接起来 | 现场互动工坊、源码、模块规格、本地运行指南 |
| 第三：教学、社群或活动演示组织者 | 希望多人轮流尝试，并解释一次命令如何变成动作 | 独立房间、预录演示、交互时间线与物理结果 |

第一类用户不必先安装 Python、购买机器人或配置自己的灵矽设备，就能使用已配置好的公网演示服务。演示资源有限：默认最多 10 个房间、4 个同时加载的物理世界，同房间语音独占；这不代表已验证大规模公众访问。

## 3. 价值来自哪里

| 受益方 | 当前产品机制 | 预期价值 | 尚待验证 |
|---|---|---|---|
| 潜在购买者 | 从观看演出转为亲口指挥，能改令、停止、检查结果 | 降低理解与试用成本，形成更具体的购买预期 | 新用户能否独立完成体验、能否分清仿真与实机 |
| MicroDuck 爱好者与开发者 | 官方模型和策略接入、可复现的语音与场景代码 | 减少搭建演示链路的起步工作，启发后续玩法 | 是否有人实际复用、继续开发或贡献 |
| 硬件与灵矽生态 | 可操作的语音到动作示例，而不止功能说明 | 让用户理解硬件与语音服务组合后的用途 | 是否带来有效咨询、开发接入或购买；目前无合作与归因数据 |
| 项目维护者 | 持续记录加载、识别和响应阶段的耗时 | 找到阻碍首次体验的问题，按证据优化 | 优化是否改善任务完成率和用户评价 |

帮助用户发现“不适合我”同样有价值。项目不应通过隐藏限制来追求购买意愿，也不应把播放次数、GitHub Star 或低延迟直接当成销售转化。

官方产品页已经提供[仿真器入口](https://pollen-robotics.com/microduck/)。DuckKing 的增量是中文语音接入、有趣的场景编排、可中途修改的受限任务，以及可追溯的交互结果和体验统计；官方模型、策略和物理引擎分别注明来源。本项目不是官方销售渠道，也没有已确认的商业合作。

## 4. 产品体验：看懂、试用、改变结果

下面是建议的 **3–5 分钟首次体验安排**，可以通过现有页面完成，不是已实现的自动新手引导，也不是实测完成时长。场景加载和用户操作会影响总耗时。

| 阶段 | 用户操作与现有页面 | 用户应得到的认识 |
|---|---|---|
| 看一幕 | 在[演示剧场](https://ztmonitor.qbox.net/duckking/demos.html)选择四鸭坐站合唱；无需真人发言，按页面操作启用声音 | 小鸭可以通过动作和编排形成有趣的表演；音乐来源有明确标识 |
| 亲口指挥 | 在[物理实验室](https://ztmonitor.qbox.net/duckking/scenarios.html)加载球场，选择灵矽云端、连接并按住说话，例如指定左脚踢球 | 中文语音确实经过灵矽，动作有物理结果；左右脚不是同一段动画 |
| 改变结果 | 在[现场互动工坊](https://ztmonitor.qbox.net/duckking/studio.html)选择“评委当指挥”，点名 C 先唱，再将下一位改为 B | 自己的命令能改变待唱顺序；当前歌手唱完后交接，不能把修改未来队列理解为立即切歌 |
| 了解边界与下一步 | 阅读本页能力边界，按兴趣进入[本地开发指南](DEVELOPMENT.md)或官方产品页 | 分清官方硬件能力、项目仿真扩展与待验证部分，再决定是否继续了解或购买 |

首次体验以一到两个主动任务为主，不要求看完十三幕。没有麦克风或暂不授予权限时，可用预录演示和本地排练了解玩法；这两种结果明确标为本地内容。

### 让人记住的三个设计点

- **命令能改变正在发生的事。** “下一位换 B”、新计划替换旧计划、搬运时暂停再继续，比只播放完整剧本更容易让人理解语音交互的用途。
- **身体动作参与表达。** 轮到独唱才站起、唱完坐下，或在桌上跌落后恢复，形成可记住的画面；合唱与跌落剧情有本地编排，不能描述成云端即兴创作。
- **结果可以检查。** 踢球看真实接触和位移，任务看完成、取消或失败；只听到“好的”不算完成。桌上跌落并非每次都能恢复，失败会明确显示。

### 首次使用与失败恢复

模型、场景、语音连接分别有状态，不把“正在加载”当成已经可以操作。iPhone 首次使用先点“启用／测试声音”；麦克风权限不等于播放权限。按住说话、松开发送，回答时可打断并开始新命令，单次录音上限 15 秒。

停止、取消、重置和重新连接都是体验的一部分。资源满、连接中断或物理动作失败应说明原因，不把旧结果当作新命令成功，不在真实后端失败时静默切成动画。恢复问题和回归经验集中在 [工程经验](LESSONS_LEARNED.md)。

## 5. 当前能力与承诺边界

| 能力 | 当前状态 | 不能据此承诺的内容 |
|---|---|---|
| 首页动作与外观 | 官方外观，脚本驱动的动画预览 | 首页画面不证明物理平衡、接触或实体动作 |
| 物理实验室与演出 | 进程内 MuJoCo、官方 ONNX 策略、项目场景与调度；另有独立 robotd/MuJoCo 适配 | 仿真结果不等于实体硬件验收，不是本项目训练了官方策略 |
| 真实灵矽交互 | 云端识别、对话、MCP 工具调用及语音回复，用户可以打断 | 不承诺每次自然语言都正确，不是已在实体 MicroDuck 内安装灵矽 |
| 本地优先 | 首页和物理实验室支持服务器离线识别；完整匹配则执行，未匹配再转交灵矽 | 本地命中用提示音和文字确认，不是灵矽云端回答；工坊真人语音固定走灵矽 |
| 自动演示与音乐 | 十三幕；预录本地对白与灵矽实连预录指令可切换；第 10–12 幕均为本地音乐与物理编排 | 本地合唱不是灵矽生成歌声，也不是官方 BLE 多机同步 |
| 搬运与感知 | 实验嘴部夹持固定轻棒；发现同伴使用仿真位置、视野及射线遮挡 | 不支持任意物品抓取；没有手臂，也没有接入摄像头识别 |
| 声音身份 | 有鸭嗓试听素材、音色配置与克隆接入脚本 | 没有已验收的克隆成品；试听不是训练成功 |

全部能力、例外和音源说明见 [README](../README.md)、[演示剧场](DEMO_THEATRE.md)、[互动工坊](INTERACTIVE_STUDIO.md)与[第三方来源](../THIRD_PARTY.md)。购买官方硬件后，不能直接假定获得 DuckKing 的全部软件玩法或相同效果。

## 6. 商业路径与成本假设

**当前阶段：验证体验是否帮助人理解产品。** 项目提供公开演示与开源代码，没有付费试用、订阅、支付、联盟返佣或订单系统。近期应先证明用户能完成一次有意义的交互，而非先为演示定价。

**可能的后续价值：为硬件和语音生态提供体验入口。** 如果用户验证支持，可进一步探索经授权的官方体验合作、开发者入门示例、教学与社群活动。咨询、购买和灵矽接入均是待验证的结果；未来合作的收入、收费对象和分配方式尚未确定，不作为当前收入。

成本包括 MuJoCo 计算、离线识别推理、模型与音频传输、灵矽调用以及维护。完整命中的本地动作可以减少该轮云端调用，但本地推理和服务器资源仍有成本。需要结合实际资源与账单计算每次有效体验的成本；现有延迟统计不足以证明节约了多少费用。

官方模型与项目原创代码的许可不同，部分模型采用 CC BY-NC-SA 4.0，音乐也有独立来源。商业发行或收费服务的设计需分别核对对应许可和授权，不能用本项目 MIT 许可覆盖它们；具体来源记录在 [THIRD_PARTY.md](../THIRD_PARTY.md)。

## 7. 如何判断产品有用

**核心验证问题：一个第一次接触 MicroDuck 的用户，能否完成自己选择的语音任务，并说清它能做什么、哪些仍只是仿真。** 这是产品目标，目前没有完成用户研究，也没有已测得的产品转化率。

| 指标 | 当前可获得的证据 | 解释与下一步 |
|---|---|---|
| 模型／场景可见延迟 | [使用体验页](https://ztmonitor.qbox.net/duckking/experience.html)的样本数、均值、P50/P90/P95，可按缓存、设备大类、版本筛选 | 从浏览器观察；可见计时到绘制后的动画帧，不是屏幕出光 |
| 本地／灵矽识别、动作回执、首段音频延迟 | 浏览器端与服务器端分别聚合，并区分交互、自动演示、验收来源 | 动作回执不代表已经发生位移，音频到达不代表扬声器出声；缺失不能补零 |
| 第一次有意义的任务是否成功 | 当前有逐轮诊断、任务状态和实际物理结果 | 还需事先定义用户目标、人工核对意图和结果；现有页面不自动给出新用户首次成功率 |
| 用户是否理解能力与边界 | 尚无产品调查 | 体验前后用简短问题询问用途和限制，记录不能完成或容易误解的地方 |
| 是否值得继续了解或购买 | 尚无咨询／购买归因 | 先记录自愿反馈及理由；后续即使有官网点击，也不能当成实际订单 |
| 开发者是否能继续探索 | 源码、指南和验证入口已提供 | 通过实际复现、问题与贡献验证；Star 数不等于开发成功或活跃用户 |

持续体验库保留技术观测，不保存识别正文、录音、IP 或用户身份；测量 ID 也不是用户 ID，因此不能用现有数据计算 DAU、用户留存或完整购买漏斗。逐轮语音诊断是另一条链路，可能含脱敏后的识别文本，不能把两者混为匿名用户分析。数据定义与丢失边界见 [持续使用体验口径](EXPERIENCE_METRICS.md)。

建议下一步邀请 10–20 名尚未购买 MicroDuck 的参与者做一次小规模试用：使用上述体验路径，记录独立完成、需要帮助、放弃及原因；询问“你现在想用它做什么”“哪些能力还需要实机确认”“是否愿意继续了解，以及为什么”。这是待执行计划，不能用当前同一句合成口令的延迟基准替代。反馈收集应另行说明用途，不向技术统计库混入身份与访谈正文。

## 8. 下一步施工顺序

| 顺序 | 待做工作 | 完成后如何验收 |
|---|---|---|
| 1 | 基于现有页面设计简短的首次体验引导，先看一幕，再尝试一条真实灵矽命令 | 新用户知道从哪里开始、当前走哪条语音路径、如何停止；通过首次试用记录验证 |
| 2 | 优先处理首屏／场景加载、句首保留、播放与切场恢复问题 | 对照相同版本和来源的浏览器 P50/P95、失败记录与完整任务复测；不混用服务器基准 |
| 3 | 在体验结束处增加清楚的能力边界、继续探索入口和可选反馈 | 用户能区分官方能力与项目扩展；反馈和外链点击不误计为购买 |
| 4 | 接上实体 MicroDuck，逐项验证灵矽、动作、停止与故障处理 | 留下实机、版本、命令和实际结果证据，再更新可承诺的功能 |
| 5 | 根据真实需求讨论生态合作与成本承担 | 有用户验证、实际成本和必要授权后再确定商业形式 |

第 1、3 项是拟议的新界面工作，本次仅补充产品文档；第 2 项已有体验数据与回归机制，后续继续按证据优化。不会将这些计划写成已上线能力。
