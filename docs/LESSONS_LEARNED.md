# 工程经验与回归检查

这里保存 DuckKing 已遇到问题的可复用结论。当前行为以代码和 [架构规格](ARCHITECTURE.md)为准；测试数量、延迟及覆盖率必须查 [验证记录](VALIDATION.md)对应提交。失败案例用来指导复验，不作为“所有类似问题已解决”的承诺。

## 先分清现象发生在哪一层

同一次操作分别核对：浏览器是否采到音频 → 实际本地／云端路由 → STT 是否完整 → 工具是否受理 → 动作是否完成 → 物理是否稳定 → 音频是否到达／播放。房间号、时间和轮次要能对应；界面停在“思考”、球继续移动、听不到声音可能是不同问题。

| 已遇到的问题 | 机制与当前做法 | 后续回归要保留的断言 |
|---|---|---|
| 句首丢失、短口令只剩后半句 | 每轮申请麦克风和初始化会错过句首；连接时静音预备，按下立即分帧，同步等待期间有界暂存 | 首帧、短按完整句、发送顺序、未按住不上传、迟到授权不附着到新连接；见 `frontend/tests/audio-output.spec.js` |
| iPhone 有麦克风权限但听不见 | 录音权限不等于播放已解锁；共享音频上下文，用户手势中启用／测试声音 | 排队音频恢复、打断清旧队列、有限缓冲；播放节点结束不声称扬声器已出声，手机仍需实听 |
| “正在思考”长期不结束 | 云端连接和回复可能无进展；阶段超时、整轮上限、一次恢复与手动重置 | 取消工具先停止动作；慢网络关闭不阻塞停止；不重发旧录音；真实物理进展与冻结状态区别对待；见 `tests/test_voice_recovery.py` |
| 本地命中后期待灵矽语音 | 动作可能全在本地完成，静默等待云端会误判为卡死 | 页面显示实际路由、本地完成文字和提示音；未调用云端就不写 TTS 成功；见 `frontend/tests/local-voice.spec.js` |
| 球位移增长到数百米 | 旧球地接触仅有滑动摩擦，纯滚动缺少耗散；只为球地接触增加滚动摩擦，显示实际球速 | 完成动作后继续推进真实物理；左／右／连续左右脚都停稳，后续漂移受限，不钳制位置／速度／显示；见 `tests/test_simulation.py` |
| 初始化过早可点、切换时模型错配 | 页面、房间、状态流和模型异步完成；首个状态前禁用选场景，用 revision 配对几何 | 初始化等待、旧响应不覆盖新场景、取消和重试后可再次操作；缓存几何不能复用旧姿态；见 `frontend/tests/scenarios.spec.js` 与 `model-loader.test.js` |
| 桌下鸭站起后不续舞或漂移越界 | 离桌后的速度交接可能把鸭留在桌脚附近；以实际触地为条件完成向外步态，再站稳续舞 | 改变起演前等待时间；验证实际触地、站稳、左右腿摆幅和 14 cm 边界，不移动根位姿补成功；见 `tests/test_table_choir.py`、[PR #34](https://github.com/zhoutingunl/DuckKing/pull/34) |
| 身体做了，工具回复却失败 | 完整链路还包括诊断和工具结果序列化；只检查动作层会漏掉统计／协议异常 | 动作 → 诊断 → MCP 结果完整返回，未知工具和缺失字段可控失败；见 [结果回传修复](VALIDATION.md#第-13-幕语音结果回传修复2026-10-26) |
| CI 偶发错过按钮或独唱窗口 | 固定睡眠和测试进程往返不代表浏览器已进入目标状态 | 权限、首帧、实际开唱等事件显式同步；保留真实物理／声音顺序，不只重跑到绿；见 `frontend/tests/scenarios.spec.js`、`studio.spec.js` |
| 历史部署覆盖率丢失 | 发布目录会被清理，历史报告不能只存那里 | 独立持久化、准确 SHA 关联、损坏输入不覆盖旧数据、缺失不借用最新值；见 `tests/test_coverage_history.py` |
| 延迟数字好看但不代表用户体验 | 服务器合成口令基准缺少手机网络、页面加载和设备差异 | 浏览器／服务器分开；本地／云端／转交分开；日常／演示／验收分开；缺失不补零，同时看样本量和失败率；见 [统计口径](EXPERIENCE_METRICS.md) |

语音与物理案例的最新发布证据见 [PR #36](https://github.com/zhoutingunl/DuckKing/pull/36)及其 [验收摘要](https://github.com/zhoutingunl/DuckKing/releases/download/deploy-yzh737-20261026T173613Z/public-acceptance.json)。界面错误、协议替身、真实 MuJoCo、真实云端和手机实听属于不同证据层级，记录时写明实际测了哪一层。

## 场景切换的复验方式

静态按钮能点通还不够。针对切换故障，从有动作正在运行的场景出发，验证切到目标场景、停止、重置后仍可继续；再检查加载失败重试、状态通道断开恢复、语音等待期间切换及下一轮新命令。错误发生时先保存上下文和日志，再恢复页面，避免只留下“刷新后好了”。

PR #36 排查时做过五个练习场场景的 20 个有向切换；该批公网证据属于前一部署提交 `f592cb1`。后续 `d78087f` 发布另验证真实云端等待期间切换及下一轮语音，具体范围在验收附件中分开记录。20 个组合不是覆盖全部浏览器、所有并发时序的证明，也没有全部作为固定 CI 测试宣称。

## 让教训继续生效

- 行为约束落在实现和相应回归检查里；长期协作规则写入 [AGENTS.md](../AGENTS.md)或 [CONTRIBUTING.md](../CONTRIBUTING.md)，经验文档本身不能替代测试。
- 修改能力、接口、容量、生命周期或默认值时，同步 README、架构和对应使用说明；检查是否还有“两个房间”“十二幕”“松手停止轨道”等旧表述。
- 截图、录屏、覆盖率和性能样本标明采集提交。历史记录保留日期和范围，不能只改标题就变成当前证据。
- 发布先检查安装和真实接口，再记录成功；ai_gateway 共享入口与 DuckKing 独立服务的边界不变。技术统计、覆盖率和身份放在版本目录外。
- 复现材料中的录音、识别正文、设备标识和凭证不直接入库。原始材料留在私有目录，公共文档只保留必要机制、脱敏摘要和可公开的证据链接。

完整存放位置和人与 AI 的更新责任见 [AI 协作说明](AI_COLLABORATION.md#经验规则和证据放在哪里)。
