# 闪身步与狗熊哆嗦毛

这两个节目是针对 Micro Duck 的机器人改编：闪身步突出左右错身与重心转换，狗熊哆嗦毛突出轻蹲、摆身和有节拍的抖头。采用已有步态和站姿策略，编排高层速度、头部与身体姿态意图。

动作意象参考了[舞蹈教材参与者对两种动作的说明](https://xinwen.bjd.com.cn/content/s6ac1e78fe4b039a8e2f1eae8.html)。机器人关节结构不同，当前版本不等同于人类舞者的完整脚法和手臂动作。

## 使用方式

工作台有「闪身步」「狗熊哆嗦毛」两个按钮，也可选择本地优先识别或连接灵矽后说：

- “来一段闪身步。”
- “来一段狗熊哆嗦毛。”

对应工具是 `duck_flash_step`、`duck_bear_shake`，均不需要参数。新连接会通过 MCP 发现这两个工具；已有语音会话需要断开后重连。项目专用智能体已追加这两个动作的工具映射，保留了原有角色提示词。

默认时长都是 3 秒。REST API 可指定 2.4–3 秒；动作使用固定编排速度，不接受 `speed` 参数。目前物理仿真实测采用默认 3 秒。

```json
{"name":"flash_step"}
```

```json
{"name":"bear_shake"}
```

## 闪身步

| 默认时间 | 节拍 | 指令意图 |
|---|---|---|
| 0–0.36 秒 | 预备 | 轻微沉身、侧看，幅度平滑起落 |
| 0.36–1.26 秒 | 左闪 | 向侧面移动，配合少量前进、转向和头部错位 |
| 1.26–2.28 秒 | 回闪 | 反向侧移与转向，头部跟随节拍 |
| 2.28–3 秒 | 收势 | 停步，轻点头，回到中立姿态指令 |

横向指令峰值为 ±0.28 m/s，前向不超过 0.12 m/s，转向不超过 0.45 rad/s。位移量由现有步态实际执行，不保证严格回到起点。

走动阶段明确关闭 `robot.pose` 的 `active` 标志。官方控制器在站姿模式中会将步行速度置零，因此不能同时保持站姿模式并期望横移。

## 狗熊哆嗦毛

| 默认时间 | 节拍 | 指令意图 |
|---|---|---|
| 0–0.48 秒 | 轻蹲 | 平滑降低身体目标，头部微低 |
| 0.48–2.52 秒 | 抖毛 | 四个左右摆动周期，头部转动、侧倾和身体起伏配合 |
| 2.52–3 秒 | 收势 | 平滑恢复高度与头部姿态，撤销站姿模式 |

该动作不发送平移或转向速度。身体高度偏移请求约 −0.010 至 −0.013 m，身体侧倾峰值 0.075 rad，头部偏航增量峰值 0.20 rad、侧倾增量峰值 0.07 rad。上述是请求参数；官方策略会滤波，实际运动幅度会更小。

## 执行、停止和异常

- 每 50 ms 计算一帧，预览和官方适配器共用同一份编排。
- 阶段变化记录在事件中，当前执行记录含 `phase` 字段。
- 相同请求 ID 重试不重复表演；新动作会取消旧动作。
- 点击停止或按 Esc，会取消动作并归零速度、关闭站姿模式、恢复动作开始前的头部目标。
- 停止确认失败时仍尝试恢复身体和头部，并返回失败，避免错误报告成功。
- 官方适配器在遥测过期、跌倒、卸力或被提起状态下拒绝继续发送动作。
- 头部角度按当前模型范围约束；身体姿态超出上游训练范围会被拒绝。

## 重新录制

动画预览：

```bash
cd frontend
DUCKKING_DEMO_SEQUENCE=choreography npm run record:demo
```

官方仿真启动并在 8767 端口运行适配工作台后：

```bash
external/microduck_rl/.venv/bin/python scripts/record_physics.py \
  --rl-root external/microduck_rl --sequence choreography \
  --output docs/media/choreography-physics.mp4
```

真实语音录制可设置 `DUCKKING_EXPECT_ACTION=flash_step` 或 `bear_shake`，并使用独立的 `DUCKKING_RECORD_LABEL`。录制程序会检查本次真实请求执行了指定动作，旧日志中的完成记录不能充当本次通过证据。
