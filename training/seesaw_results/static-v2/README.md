# 静态跷跷板 v2 历史实测工件

本目录归档提交 `50dbf00` 的静态板面采样和评估记录；当前网页已改用移动配重任务，不读取这里的成绩。网络为数值 JSON，服务无需 PyTorch。物理、观察和奖励定义见 [设计说明](../../../docs/SEESAW_COACH.md)。

## 最终独立测试

训练种子 42；验证环境种子 20000–20019；独立测试环境种子 30000–30099。三个控制器使用同一组测试种子，标准回合 12 秒。

| 控制器 | 成功 / 回合 | Wilson 95% 区间 | 平均绝对倾角 |
|---|---:|---:|---:|
| 任务 PPO + 官方步态 | 88 / 100 | 80.2%–93.0% | 0.717° |
| 官方步态站定 | 0 / 100 | 0.0%–3.7% | 5.521° |
| 人工位置/倾角反馈规则 | 41 / 100 | 31.9%–50.8% | 1.259° |

平均绝对倾角先在各回合内对任务 tick 取平均，再对回合取平均。成功要求完整回合末连续 2 秒满足水平、支点距离和支撑条件，不能把板面停在限位上计成功。100 个环境种子来自一次训练，不是 100 次独立训练；此成绩不证明对其他板面参数或实体机器人的泛化。

## 训练经过与计时

1. `correction-report.json` / `correction-policy.json`：第一阶段低走动成本奖励，实际采样 65,536 步，选中 40,960 步策略。CPU 墙钟 574.60 秒；独立测试 39/100。学会纠偏，但会频繁切换动作。
2. `stationary-reward-report.json`：增加稳定站定奖励后，从随机策略重新训练，验证停留在 0/20；在 39,807 步主动取消，墙钟 285.25 秒。没有做最终独立测试，不能记为 0/100。
3. `report.json`：继承第一阶段的 40,960 步 actor，增加保持时间和回合进度两个输入，再学习稳定站定。新输入权重为零，critic 和优化器重新初始化。本阶段采样 131,072 步，墙钟 1,391.57 秒（23 分 12 秒，含采样、验证和三个控制器的最终测试）。

本阶段第 98,304 步在 880.49 秒（14 分 40 秒）达到预先约定的“连续两次验证至少 18/20”门槛。该时间不包含前两个实验，不代表从随机策略开始的收敛耗时。达到验证门槛也不等于所有未来回合都成功。

演示使用验证最优 checkpoint：继承 40,960 步 + 本阶段 8,192 步，工件 `steps=49152`。它在验证集上是 20/20；之后继续训练并非单调改善，所以没有使用最后一次更新。测试集仅在最终选择后评估。

- `policy.json`：选中的 14 输入、64×64 tanh、3 输出离散 actor。
- `early.json`：本阶段开始时的 actor，继承第一阶段 40,960 步，**不是随机未训练网络**。
- `environment.json`：实际 Python、MuJoCo、ONNX Runtime、SB3、PyTorch 版本。Intel macOS，单采样进程、单 Torch 线程，同时存在开发/验证负载；没有 GPU 或服务器训练的暗示。
- `correction-policy.json` SHA-256：`41435737bd40547c0acfbac9804e48312cfcdf052dcb2d4e0fb146161eae6688`，与最终报告的初始化来源一致。

## 历史复现命令（提交 50dbf00）

以下命令对应提交 `50dbf00` 的训练代码与当时目录结构。需在该提交的独立 checkout 中使用 CPU 解释器执行；当前移动配重脚本已经使用新契约，不能直接重跑这个历史阶段：

```sh
PYTHONPATH=src .duckking/balance-venv/bin/python training/train_seesaw.py \
  --output .duckking/seesaw/reproduce --steps 131072 --seed 42 \
  --warm-start training/seesaw_results/correction-policy.json
```

省略 `--warm-start` 会从随机任务策略开始，是另一个实验，不保证重现这里的成功率。该历史提交的脚本实现 `seesaw-v2-settle`；第一阶段旧奖励的历史记录和初始化 actor 一并保留，不声称该提交的 CLI 能原样重跑第一阶段旧契约。不同平台数值库可能导致学习轨迹和耗时差异。

原始报告保留逐次验证、优化器指标和各测试种子的成功/失败结果；失败样本未剔除。后续换物理模型必须重新评估，不能仅修改报告中的模型哈希。
