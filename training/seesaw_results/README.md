# 移动配重跷跷板 CPU PPO

当前契约是 `seesaw-v3-counterweight`。物理与奖励定义见 [设计说明](../../docs/SEESAW_COACH.md)，旧静态任务全部归档在 [static-v2](static-v2/README.md)，不能沿用其 88/100 成绩。

## 本次实测结果

单线程 CPU，新增采样 **131,072 步**。在第 **49,152 步、552.53 秒（约 9 分 13 秒）**达到连续两次验证至少 18/20 的预设门槛；本阶段含采样、验证和 400 个最终对照回合共 **1,612.98 秒（约 26 分 53 秒）**，不包含旧静态任务训练时间。

最终选中本阶段 131,072 步的 checkpoint，工件步数 180,224 = 继承 49,152 + 本阶段 131,072；这表示 actor 来源步数，不是历次所有试验消耗的总步数。

| 控制器 | 成功 / 100 | Wilson 95% 区间 | 平均绝对倾角 | 平均水平时间占比 |
|---|---:|---:|---:|---:|
| 任务 PPO | 99 | 94.6%–99.8% | 0.443° | 98.15% |
| 只回中心站定 | 0 | 0.0%–3.7% | 4.308° | 4.44% |
| 官方站定 | 0 | 0.0%–3.7% | 5.392° | 2.92% |
| 人工配平反馈 | 76 | 66.8%–83.3% | 1.156° | 86.02% |

倾角先对各回合所有任务 tick 取平均，再对回合平均；水平时间占比按各回合前 2 秒之后计算。PPO 有 1 个失败回合（种子 30025），末尾连续稳定条件未满足；原始记录保留，不把接近水平当作必然成功。回中规则 0/100 说明当前移动负载下，固定回中心不是通用解。

## 实验身份与选择方式

- 真实 MuJoCo 被动板面，0.28 kg 配重由独立滑轨位置执行器驱动。板角没有驱动器，运行中不改写板面、配重或鸭子位姿。
- 18 秒回合；前 2 秒后至少 70% 时间满足水平/角速度/支撑条件，末尾连续 0.5 秒稳定，无跌倒或越界。不要求站在中心。
- 一个训练随机种子 42；环境训练种子从 520001 开始，验证使用 20000–20019，最终测试使用 30000–30099。
- 继承静态任务 `static-v2/policy.json` 的 49,152 步 actor，新增四个输入列为零，critic 和优化器重新初始化。报告记录源/目标模型哈希；这是跨任务迁移，不是从零训练。
- 每 8192 步评估一次；按验证成功率、其次平均回报选 checkpoint。测试集不用于选择。
- `policy.json` 为验证最优策略，`early.json` 为本阶段起始策略；两者都是数值 JSON，不需要服务器安装 PyTorch。
- `report.json` 保留真实训练指标，以及 PPO、官方站定、回中站定、人工配平四个控制器逐个测试回合的结果。100 个环境种子不等于 100 次独立训练。

## 复现

独立 CPU 解释器依赖见 `training/requirements.txt`。从仓库根目录运行，输出目录必须尚不存在：

```sh
PYTHONPATH=src .duckking/balance-venv/bin/python training/train_seesaw.py \
  --output .duckking/seesaw/moving-reproduce --steps 131072 --seed 42 \
  --warm-start training/seesaw_results/static-v2/policy.json
```

省略 `--warm-start` 会从随机任务策略开始，属于另一个实验。不同平台数值库可能改变训练轨迹；报告中的 CPU 墙钟时间包含实际开发负载下的采样和评估，不是独占机器基准，也不包括静态策略的历史训练时间。

当前任务有明确先验：冻结的官方步态、横移/朝向工程反馈、按真实质心计算的重力合力矩观察与奖励、固定质量配重。人工配平规则直接使用这些物理量，可能优于 PPO，必须如实并列展示。这个实验不证明实体迁移或未见质量、速度、倾角条件的可靠性。
